+# React Dialog primitive
+
+这是一个无产品样式、无业务文案的 React Dialog primitive。包以 ESM 发布，当前支持 React 19，运行时依赖消费者提供的 `react` 与 `react-dom`。浏览器基线是支持 `HTMLDialogElement.showModal()` 的现代浏览器。
+
+## 实现边界
+
+- `Dialog.Root` 是打开状态的唯一所有者。传 `open` 时由消费者控制；否则使用 `defaultOpen` 初始化内部状态。
+- `Dialog.Portal` 只在客户端挂载后创建 portal。服务端和水合首帧都不访问 `document`，所以即使 `defaultOpen` 为 `true` 也不会产生不同的服务端树。
+- `Dialog.Content` 使用原生模态 `<dialog>`。浏览器负责 top-layer、背景 inert、焦点约束以及嵌套时只把 Escape 发给最上层 Dialog；primitive 负责把这些事件转换回 React 状态，并在卸载后恢复原焦点。
+- `Dialog.Title` 与 `Dialog.Description` 提供稳定的 `aria-labelledby`、`aria-describedby` 关系。若使用 `aria-label`，可省略 Title；Description 仍应存在，或由消费者显式提供另一个 `aria-describedby` 目标。
+- 内容、文案、业务操作和视觉样式属于产品。所有 DOM 组件都接受原生属性、`className`、`style` 和转发 ref；`data-state` 可用于状态样式。
+
+## 公开 API
+
+```tsx
+import { Dialog } from '@fixture/react-dialog'
+
+<Dialog.Root defaultOpen={false} onOpenChange={(open, details) => {}}>
+  <Dialog.Trigger className="productTrigger">Edit profile</Dialog.Trigger>
+  <Dialog.Portal>
+    <Dialog.Content className="productOverlay">
+      <section className="productPanel">
+        <Dialog.Title>Edit profile</Dialog.Title>
+        <Dialog.Description>Update your public information.</Dialog.Description>
+        {/* product fields and actions */}
+        <Dialog.Close>Close</Dialog.Close>
+      </section>
+    </Dialog.Content>
+  </Dialog.Portal>
+</Dialog.Root>
+```
+
+| 导出 | 公开契约 |
+| --- | --- |
+| `Dialog.Root` / `DialogRoot` | `open`、`defaultOpen`、`onOpenChange(open, { reason })`；reason 为 trigger、close-button、escape-key 或 outside-press |
+| `Dialog.Trigger` / `DialogTrigger` | 原生 button props 与 ref；组合消费者 `onClick`，被 `preventDefault()` 时不打开 |
+| `Dialog.Portal` / `DialogPortal` | 默认 portal 到 `document.body`，也可传 `container` |
+| `Dialog.Content` / `DialogContent` | 原生 dialog props 与 ref；支持 `initialFocus` 和 `restoreFocus`；消费 `onCancel` 或 `onClick` 的 `preventDefault()` |
+| `Dialog.Title` / `DialogTitle` | 可访问名称与原生 h2 props/ref |
+| `Dialog.Description` / `DialogDescription` | 可访问描述与原生 p props/ref |
+| `Dialog.Close` / `DialogClose` | 原生 button props/ref；文案由产品传入 |
+
+受控用法只需把同一个状态回写给 Root：
+
+```tsx
+const [open, setOpen] = useState(false)
+
+<Dialog.Root open={open} onOpenChange={setOpen}>
+  {/* the same composition */}
+</Dialog.Root>
+```
+
+若产品需要打开后聚焦危险操作或另一个特定控件，把它的 ref 传给 `Dialog.Content initialFocus`。默认由浏览器选择第一个可聚焦元素。只有当产品在关闭回调中明确安排了下一焦点时，才应使用 `restoreFocus={false}`。

+## 三个产品的迁移方案
+
+1. 各产品先保留自己的 `ProductDialog` 外观组件，把旧 props 映射到这组组合式 primitive。业务文案、按钮顺序、埋点和 CSS 类继续留在产品层。
+2. 逐个迁移现有弹窗，先对齐可观察行为。为每个旧实现记录初始焦点、Escape、外部点击和关闭后焦点去向；不把历史缺陷当兼容要求。
+3. 先在一个低风险弹窗发布 prerelease/canary，观察键盘关闭、异常和回退信号，再扩到同产品其余弹窗以及另两个产品。旧实现保留到每个产品完成核心路径验证。
+4. 所有调用方完成后，删除产品内的 focus trap、全局 keydown 和 portal 管理代码。若未来需要 alert dialog，增加独立的强约束 primitive，而不是给现有 Root 累积一组互相冲突的布尔开关。
+
+迁移回滚以产品 wrapper 为边界：在旧实现仍存在时切回 wrapper 内部即可，不要求业务调用方同时反向迁移。
