结论：把“会话面板”从可调高度抽屉的停靠流程中移出，只保留全高开关和拖拽位移；公共可调高度抽屉及其 API 保持不变。不要通过 `minHeight=maxHeight=100%` 或新增 `fixedMode` 继续走旧高度链路，否则监听和补偿仍会运行。

## 最小重构方案

| 范围 | 调整 |
| --- | --- |
| 会话面板状态 | 删除 `sheetHeight` 及 60% 停靠状态。稳定状态只剩展开、收起；短拖期间的位移由现有手势/动画值临时承载，不写回面板高度。 |
| 打开 | 直接进入全高终态。高度由容器布局决定，不再计算或同步中间高度。 |
| 头部下拉 | 达到既有关闭阈值时调用项目现有的全高收起动画；未达到阈值时把临时位移动画恢复为零。删除任何落到 60% 的分支。 |
| 高度监听 | 从会话面板挂载、更新和卸载链路中完整删除 `heightListener`、订阅清理和相关 import。 |
| WebView | 删除中间高度绘制补偿及其派生值。让 WebView 使用正常剩余空间布局，例如既有布局体系中的伸展能力；同时保证滚动容器允许收缩，避免全高下溢出。 |
| 五个参数 | 从会话面板专用的类型、组件签名、中间包装层和调用点一起删除，不能只在最外层停止传值。若其中参数属于公共可调高度抽屉且仍有其他调用者，只删除会话链路中的透传，保留公共定义。 |
| 公共抽屉 | 不修改其可调高度状态、监听器、停靠算法和其他页面的调用契约。 |

目标结构应当是：

```text
会话面板
  展开 → 全高
  头部下拉
    达到关闭条件 → 复用现有全高收起动画
    短拖 → 位移回弹至 0

公共可调高度抽屉
  保持原有多高度能力，继续服务其他页面
```

不建议为了这一个消费者给公共抽屉增加新的模式开关。若现有全高动画与可调抽屉耦合，应只提取已有的“收起动作/动画”作为窄能力复用，不把高度状态和监听一起带过来。

实施时按以下顺序收缩，可以持续依靠类型检查暴露遗漏：

1. 先将会话面板的打开、关闭和短拖回弹接到唯一的全高路径。
2. 删除 60% 决策和 `sheetHeight`。
3. 删除 `heightListener` 及生命周期代码。
4. 删除 WebView 高度补偿，恢复普通布局。
5. 从最内层开始逐层删除五个透传参数和对应类型。
6. 清理已无引用的常量、计算函数、测试夹具和样式。
7. 不触碰仍被其他页面使用的公共抽屉实现。

## 验证计划

自动化验证：

- 类型检查和项目既有 lint/build 通过，确认五个参数没有残留调用或可选参数兜底。
- 会话面板打开后直接稳定在全高，不出现 60% 中间终态。
- 头部短距离下拉并释放后回弹到全高，面板保持打开。
- 达到关闭条件后执行现有收起动画，并最终进入关闭状态。
- 快速连续拖拽、回弹过程中再次拖拽、动画中触发关闭时，最终状态仍唯一且正确。
- 更新或删除原先断言 60% 停靠、`sheetHeight` 或高度回调次数的会话测试。
- 保留公共可调高度抽屉的原有测试，并至少回归一个真实使用页面，证明中间高度、拖动和高度通知仍有效。

真机或项目支持的实际运行环境验证：

- 在至少一个有安全区的窄屏设备和一个较高视口打开会话面板，检查顶部、底部、遮挡和滚动可达性。
- 使用真实 WebView 内容检查首次展示、加载完成和内部滚动；不应出现中间高度空白、二次跳高或底部内容不可达。
- 确认只有头部手势触发面板下拉，WebView 内部纵向滚动不误触关闭。
- 观察短拖回弹和完整收起的中断行为；若项目支持减少动态效果，同时验证该路径。
- 通过日志、断点或性能面板确认会话面板挂载及拖动期间不再注册高度监听，也不再触发中间高度补偿绘制。
