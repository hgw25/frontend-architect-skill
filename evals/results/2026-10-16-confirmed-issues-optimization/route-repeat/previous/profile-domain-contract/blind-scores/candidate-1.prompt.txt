## 核心决定

`user` 与 `developer` 是两个独立身份域：

- 个人主页使用 `userId`。
- 应用作者只有 `developerLogin`。
- 禁止把 `developerLogin` 当作 `userId`，也不能生成 `/users/{developerLogin}`。
- `GET /users/{userId}` 返回的是“当前查看者有权看到的 applications”，本人可收到公开和私有应用。前端完整展示服务端返回值，不再做公开性过滤。
- 旧生成注释已经过时，应修改生成源并重新生成，不能手改生成文件后留下下一次生成会复现的问题。

## 路由

新增公开可进入的详情路由：

```ts
{
  path: '/users/:userId',
  name: 'user-profile',
  component: () => import(/* 个人主页页面 */),
  props: route => ({ userId: String(route.params.userId) }),
}
```

具体路径和文件名沿用项目现有 Vue Router 约定。

路由不应因为“可能包含私有应用”而加前端登录守卫。请求是否返回私有应用由服务端根据会话决定，路由守卫不能承担授权职责。

页面必须支持：

- 地址栏直达、刷新和前进后退。
- 同一组件内从一个 `userId` 导航到另一个时重新请求。
- 无效或不存在的用户按照现有 API 状态码约定展示错误。
- `userId` 只来自路由，不复制进全局 Store。

## 数据流

```text
/users/:userId
       ↓
个人主页页面
       ↓
用户领域数据访问层
       ↓ 携带现有会话
GET /users/{userId}
       ↓
{ profile, applications }
       ↓
页面直接渲染服务端筛选后的 applications
```

前端领域类型应表达真实含义：

```ts
interface UserProfilePageData {
  profile: UserProfile
  applications: ApplicationSummary[]
}
```

不要命名为 `publicApplications`，也不要执行类似：

```ts
applications.filter(app => app.visibility === 'public')
```

实现注意点：

- 复用现有 HTTP 客户端、认证传递和错误处理。
- 请求状态由页面或现有查询机制负责，至少区分 loading、success、error。
- 路由参数变化时取消旧请求，或忽略已经过期的响应。
- 没有跨页面复用需求时，不新增全局 Store。
- 应用是否标记“私有”，只取决于响应中是否已有可靠的可见性字段；没有该字段就不要推断或新增角标。

该接口响应随查看者身份变化，缓存必须按身份隔离：

- 登录、退出或切换账号后，清除或失效该用户主页查询。
- 如果现有查询缓存不会随会话清理，查询键需包含稳定的 viewer/session scope。
- SSR、代理或 CDN 不得把本人响应作为公共缓存复用；服务端需提供适当的私有缓存策略。这是服务端契约验收项，不用前端隐藏数据来补救。
