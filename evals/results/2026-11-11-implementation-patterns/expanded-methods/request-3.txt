评审下面的架构说明，给出有来源的实际修正和验证方向，不实现应用或补造缺失服务契约。

商品目录和财务对“客户”有不同定义，API 只给各自的标识，没有两者之间的权威映射。
提案因字段都是 customerId 就在客户端强行合并并据此跳转；同时将每个页面文件夹
都命名为一个 bounded context。金额以 number 存储，却允许比较不同币种而忽略币种。
另一处资料页保存后返回回执，再读取列表。提案把它称为“严格 CQS 和完整 CQRS”，
要求丢弃回执以满足命令没有返回值，并把 Redux 调试 action 日志称为 Event Sourcing。
如果“重放历史”，方案会重执行 action 内的发邀请 HTTP 调用。项目没有权威事件存储，
也没有独立读写模型的需求；当前已有状态与数据层可以继续使用。
