React + TypeScript 项目目前没有 DI 容器。一个功能依赖传入的 api 对象，bootstrap
已经创建真实 api 并传给该功能；测试可以传另一实现，功能内部没有 registry lookup。
方案声称“只有安装容器并加装饰器才算 DI；用了 DI 就自动满足 DIP”。它计划把这个
已传入的 api 改为全局 container.get('api')，并将 container 继续传给所有业务方法。
项目还通过框架生命周期回调注册和清理订阅，方案又声称“没有容器就不可能有 IoC”。
不存在第二套依赖图或额外作用域需求；用户只要求把当前依赖关系维护清楚。
