+# React Dialog primitive
+
+This package provides a headless, modal Dialog for React 18.3 and 19. Product copy,
+actions, layout, and visual styles stay in the consuming application. The primitive
+owns the cross-product behavior that must not drift: ARIA relationships, controlled
+and uncontrolled state, portals, focus containment and restoration, modal isolation,
+top-layer Escape handling, and nested-dialog ordering.
+
+## Public API
+
+Import either the compound `Dialog` object or the individually named components from
+the package root:
+
+```tsx
+import { Dialog } from '@example/react-dialog'
+
+<Dialog.Root defaultOpen={false} onOpenChange={(open) => console.log(open)}>
+  <Dialog.Trigger className="trigger">Edit profile</Dialog.Trigger>
+  <Dialog.Portal>
+    <Dialog.Overlay className="overlay">
+      <Dialog.Content className="panel">
+        <Dialog.Title>Edit profile</Dialog.Title>
+        <Dialog.Description>Update your public information.</Dialog.Description>
+        {/* Product-owned form and actions */}
+        <Dialog.Close>Cancel</Dialog.Close>
+      </Dialog.Content>
+    </Dialog.Overlay>
+  </Dialog.Portal>
+</Dialog.Root>
+```
+
+- `Dialog.Root` owns state. Use `defaultOpen` for uncontrolled state, or `open` with
+  `onOpenChange` for controlled state.
+- `Dialog.Trigger` and `Dialog.Close` render buttons, forward refs and native button
+  props, and compose consumer click handlers. Calling `preventDefault()` keeps the
+  primitive from changing state.
+- `Dialog.Portal` renders into `document.body` after mount, or into its optional
+  `container`. It renders nothing on the server, so server and first hydration output
+  agree.
+- `Dialog.Overlay` renders a `div` and dismisses only the top dialog when the overlay
+  itself receives a pointer press. Prevent its `onPointerDown` to disable that policy.
+- `Dialog.Content` renders the modal `role="dialog"`, traps focus, handles Tab wrapping,
+  restores the previously focused element, and accepts native `div` props, `className`,
+  `style`, forwarded refs, and `initialFocusRef`.
+- `Dialog.Title` and `Dialog.Description` provide the generated, hydration-stable ARIA
+  relationships. A content without a visible title must receive `aria-label`. If no
+  description is appropriate, pass `aria-describedby={undefined}` explicitly.
+
+The state-bearing Trigger, Overlay, and Content components expose `data-state` where state-based styling is useful.
+No CSS ships with the package and no private DOM selector is a styling contract.
+
+## Implementation boundaries
+
+`Dialog.tsx` is the React-facing contract: state ownership, composition, DOM semantics,
+and event/ref composition. `dialog/modalManager.ts` is private and owns the browser
+lifecycle shared by all instances: the ordered modal stack, document listeners, focus
+containment, background `inert`/`aria-hidden` snapshots, and cleanup. Only the current
+top layer can dismiss or redirect focus. This split keeps a future layering change in
+one internal owner without widening the package API.
+
+The package is ESM-only. React and React DOM are peer dependencies because the host
+must provide the singleton renderer. `src/index.ts` is the sole public source entry;
+the package `exports` map exposes only `dist/index.js` and its declarations, keeping
+the modal manager private.
+
+## Test matrix
+
+| Contract | Evidence |
+| --- | --- |
+| Uncontrolled open, first focus, forward/reverse Tab wrap | Chromium behavior test |
+| Escape closes and focus returns to the actual opener | Chromium behavior test |
+| Programmatic focus cannot escape; background is inert | Chromium behavior test |
+| Nested dialogs: only the top layer closes, then local focus restores | Chromium behavior test |
+| Accessible name, description, `aria-modal`, and body portal | Chromium accessibility/DOM assertions |
+| Overlay dismissal and cleanup of modal isolation | Chromium pointer/DOM assertions |
+| Controlled `open`/`onOpenChange` | Chromium consumer fixture |
+| Server render without browser globals, including inline open content | Node SSR tests |
+| Hydration-stable trigger IDs followed by client portal mount | Server markup hydrated in Chromium with console-error assertion |
+| Public runtime/types artifact and package file list | ESM library build, declaration build, and `npm pack --dry-run` |
+
+Run the complete gate with `npm run check`. Browser tests use built IIFE fixtures
+in Playwright rather than a localhost server, so the same interactions run in network-
+restricted CI sandboxes.
+
+## Migration for the three products
+
+1. Publish a prerelease and add it beside each existing Dialog. Do not replace all
+   implementations in one release. Inventory whether each product currently closes on
+   overlay press and preserve that choice with the overlay handler during migration.
+2. In the first product, keep its existing product-level component as a compatibility
+   adapter. Move its title, description, buttons, analytics, and styling into the
+   compound children; map its current `open` callback to `Root`. Verify its key flows
+   with the matrix above and release behind the existing product boundary.
+3. Migrate the product with nested dialogs next, using a separate `Root` and `Portal`
+   for every layer. Remove local Escape listeners, focus sentinels, body-wide
+   `aria-hidden`, and focus-restoration effects as each consumer moves; retaining them
+   would create competing owners.
+4. Migrate the final product, then remove the compatibility adapters only after no call
+   sites remain. Treat changes to close policy, initial focus, DOM element types, or
+   styling hooks as consumer-visible release notes even when TypeScript signatures do
+   not change.
+
+Rollback is per product: restore its adapter to the previous implementation while the
+shared package remains installed for already-migrated products. This keeps the
+foundation release and product rollout independently reversible.

+const isolatedElements = new Map<HTMLElement, ElementSnapshot>()
+let listeningDocument: Document | null = null

+const focusableSelector = [
+  'a[href]',
+  'area[href]',
+  'button:not([disabled])',
+  'input:not([disabled]):not([type="hidden"])',
+  'select:not([disabled])',
+  'textarea:not([disabled])',
+  'iframe',

+  '[contenteditable="true"]',
+  '[tabindex]:not([tabindex="-1"])',
+].join(',')

+function isVisible(element: HTMLElement) {
+  const style = element.ownerDocument.defaultView?.getComputedStyle(element)
+  return style?.display !== 'none' && style?.visibility !== 'hidden' && element.getClientRects().length > 0
+}
+
+export function getFocusableElements(container: HTMLElement) {
+  return Array.from(container.querySelectorAll<HTMLElement>(focusableSelector)).filter(isVisible)
+}
+
+export function focusFirstElement(container: HTMLElement) {
+  const focusable = getFocusableElements(container)
+  const target = focusable.find((element) => element.hasAttribute('autofocus')) ?? focusable[0] ?? container
+
+  target.focus({ preventScroll: true })
+}
+
+function topLayer() {
+  return layers.at(-1)
+}
+
+export function isTopLayer(id: symbol) {
+  return topLayer()?.id === id
+}
+
+function restoreIsolation() {
+  for (const [element, snapshot] of isolatedElements) {
+    element.inert = snapshot.inert
+    if (snapshot.ariaHidden === null) {
+      element.removeAttribute('aria-hidden')
+    } else {
+      element.setAttribute('aria-hidden', snapshot.ariaHidden)
+    }
+  }
+  isolatedElements.clear()
+}
+
+function isolateElement(element: HTMLElement) {
+  if (!isolatedElements.has(element)) {
+    isolatedElements.set(element, {
+      ariaHidden: element.getAttribute('aria-hidden'),
+      inert: element.inert,
+    })
+  }
+  element.inert = true
+  element.setAttribute('aria-hidden', 'true')
+}
+
+function updateIsolation() {
+  restoreIsolation()
+
+  const content = topLayer()?.content
+  if (!content) return
+
+  let current: HTMLElement = content
+  while (current.parentElement) {
+    const parent = current.parentElement
+    for (const sibling of parent.children) {
+      if (sibling !== current && sibling instanceof HTMLElement) {
+        isolateElement(sibling)
+      }
+    }
+    if (parent === content.ownerDocument.body) break
+    current = parent
+  }
+}
+
+function handleKeyDown(event: KeyboardEvent) {
+  if (event.key !== 'Escape' || event.defaultPrevented) return
+
+  const layer = topLayer()
+  if (!layer) return
+
+  event.preventDefault()
+  event.stopPropagation()
+  layer.dismiss()
+}
+
+function handleFocusIn(event: FocusEvent) {
+  const layer = topLayer()
+  if (!layer || layer.content.contains(event.target as Node)) return
+  focusFirstElement(layer.content)
+}
+
+function startListening(document: Document) {
+  if (listeningDocument === document) return
+  listeningDocument = document
+  document.addEventListener('keydown', handleKeyDown, true)
+  document.addEventListener('focusin', handleFocusIn, true)
+}
+
+function stopListeningWhenIdle() {
+  if (layers.length > 0 || !listeningDocument) return
+  listeningDocument.removeEventListener('keydown', handleKeyDown, true)
+  listeningDocument.removeEventListener('focusin', handleFocusIn, true)
+  listeningDocument = null
+}

+export function registerDialog(layer: DialogLayer) {
+  layers.push(layer)
+  startListening(layer.content.ownerDocument)
+  updateIsolation()
+

+    const index = layers.indexOf(layer)
+    if (index !== -1) layers.splice(index, 1)
+    updateIsolation()
+    stopListeningWhenIdle()
+

+      const target = layer.restoreFocus
+      const activeLayer = topLayer()
+      if (target?.isConnected && (!activeLayer || activeLayer.content.contains(target))) {
+        target.focus({ preventScroll: true })
+      }
+    })
+  }

+# `@frontend-architect-eval/feature-flags`
+
+A Vite 8 plugin that exposes an explicit, typed subset of a server-side JSON
+file through `virtual:feature-flags`. It is ESM-only and supports Node versions
+supported by Vite 8.
+
+## Usage
+
+```ts
+// vite.config.ts
+import { featureFlags } from '@frontend-architect-eval/feature-flags'
+import { defineConfig } from 'vite'
+
+export default defineConfig({
+  plugins: [
+    featureFlags({
+      source: new URL('./flags.json', import.meta.url),
+      expose: ['checkoutV2', 'theme'],
+    }),
+  ],
+})
+```
+
+Add the declaration-only entry point to the consumer's TypeScript config:
+
+```json
+{
+  "compilerOptions": {
+    "types": ["@frontend-architect-eval/feature-flags/virtual"]
+  }
+}
+```
+
+Then import the runtime values from the virtual module:
+
+```ts
+import { flags } from 'virtual:feature-flags'
+```
+
+Without a project schema, flag values are typed as `boolean | number | string`.
+For exact keys and narrower values, merge the consumer-owned contract in a
+checked-in declaration file:
+
+```ts
+declare module 'virtual:feature-flags' {
+  interface FeatureFlags {
+    readonly checkoutV2: boolean
+    readonly theme: 'light' | 'dark'
+  }
+}
+```
+
+The declaration and `expose` allowlist are both reviewed public contracts: the
+declaration provides compile-time names and values, while the plugin verifies at
+runtime that every exposed key exists and contains a supported primitive.
+
+## Public contract and security boundary
+
+The package root exports `featureFlags`, `FeatureFlagsOptions`, and
+`FeatureFlagValue`. The `./virtual` export is declaration-only and exists for
+TypeScript's `types` option; it is not a runtime module. Application code must
+import values from `virtual:feature-flags`, which Vite resolves.
+
+`source` accepts a local path (relative to Vite's root) or a `file:` URL. Its
+top-level value must be an object. Only own properties named by `expose` are
+serialized, and values must be booleans, finite numbers, or strings. Everything
+else—including server tokens next to public flags—stays in Node memory. Do not
+put secrets in `expose`; client-side flags are public presentation data and are
+never an authorization boundary.
+
+Configuration failures name the option, flag, and source path, then include a
+`Fix:` action. Diagnostics intentionally omit source values so a malformed or
+invalid secret is not copied into logs.
+
+## Dev, build, HMR, source maps, and cache
+
+Dev and production builds use the same virtual-module generator. The plugin
+registers the source with Vite's watcher. A source change clears the per-plugin
+promise cache, invalidates the virtual module, and lets Vite propagate the HMR
+update (or reload the page when no accepting boundary exists). Build watch mode
+uses the same invalidation rule.
+
+The cache contains only the generated public module and is reset at each build
+start and source change. It avoids duplicate reads within one graph evaluation;
+it is never shared across Vite servers or processes.
+
+The virtual module returns a source map whose identity and `sourcesContent`
+contain only generated, allowlisted client code. The raw JSON file and its path
+are not source-map sources, preventing unexposed values from re-entering client
+artifacts through debugging metadata. The published plugin JavaScript also
+ships its TypeScript-generated source map and declaration map.
+
+## Verification and releases
+
+From the repository root, `npm run check` builds declarations and maps,
+type-checks an exact consumer schema, runs a production Vite build, exercises a
+real dev server and file-change HMR, checks actionable diagnostics, scans bundles
+and maps for an unexposed token, and installs the packed tarball in a clean
+consumer.
+
+The package begins at `0.1.0`. During `0.x`, changing option semantics, supported
+flag values, virtual-module exports, or the required consumer schema is released
+as a minor with a migration note; additive compatible changes are patches. From
+`1.0.0`, those contract changes require a major version. Deprecations should ship
+with a replacement and remain for at least one minor release. Vite peer-range or
+Node-engine increases are treated as breaking, and risky changes should first
+ship under a prerelease tag so real consumers can verify dev, build, and HMR.
