+# Headless Dialog primitive
+
+这是三个 React 产品共享的无样式 Dialog 基础组件。它只负责打开状态、语义、portal、模态层级、键盘和焦点生命周期；标题文案、说明、业务按钮与视觉样式由产品组合。
+
+发布产物是 ESM-only，peer contract 为 React/ReactDOM `>=18.3.0`，编译目标为 ES2022，并依赖现代浏览器原生 `inert`。需要覆盖不支持 `inert` 的旧浏览器时，应由产品平台统一加载 polyfill，而不是在每个 Dialog 实例中分叉行为。
+
+## 公开 API
+
+包只公开根入口 `@fixture/headless-dialog`，内部焦点管理模块不是稳定契约。既可以使用 `Dialog.*`，也可以按需导入同名的 `DialogRoot`、`DialogTrigger` 等具名导出；所有组件都转发 ref，并接受对应原生元素的属性。
+
+| 组件 | 职责 |
+| --- | --- |
+| `Dialog.Root` | 用 `defaultOpen` 管理非受控状态，或用 `open` + `onOpenChange` 管理受控状态 |
+| `Dialog.Trigger` | 触发打开，暴露 `aria-haspopup`、`aria-expanded`、`aria-controls` 和 `data-state` |
+| `Dialog.Portal` | 客户端挂载后渲染到 `document.body`；`container` 可指定宿主 |
+| `Dialog.Overlay` | 顶层遮罩点击关闭；消费者通过原生属性和 `className` 自定义样式 |
+| `Dialog.Content` | `dialog`/`alertdialog` 语义、焦点作用域、顶层 Escape；`initialFocusRef` 可指定初始焦点 |
+| `Dialog.Title` | 注册并连接 `aria-labelledby` |
+| `Dialog.Description` | 注册并连接 `aria-describedby` |
+| `Dialog.Close` | 关闭当前 Dialog，不内置文案 |
+
+`onOpenChange(open, { reason })` 的 `reason` 为 `trigger`、`overlay`、`escape-key` 或 `close-button`。消费者事件处理器会先运行；对 Trigger、Overlay、Close 的事件调用 `preventDefault()` 可以取消 primitive 默认动作，`onEscapeKeyDown` 同理。没有 `Dialog.Title` 时，消费者必须给 `Dialog.Content` 提供 `aria-label` 或 `aria-labelledby`。
+
+```tsx
+import { Dialog } from '@fixture/headless-dialog'
+
+<Dialog.Root open={open} onOpenChange={setOpen}>
+  <Dialog.Trigger className="button">Edit profile</Dialog.Trigger>
+  <Dialog.Portal>
+    <Dialog.Overlay className="overlay">
+      <Dialog.Content className="panel">
+        <Dialog.Title>Edit profile</Dialog.Title>
+        <Dialog.Description>Update your public information.</Dialog.Description>
+        {/* 产品表单和按钮 */}
+        <Dialog.Close className="button">Cancel</Dialog.Close>
+      </Dialog.Content>
+    </Dialog.Overlay>
+  </Dialog.Portal>
+</Dialog.Root>
+```
+
+## 核心边界
+
+- `Dialog.tsx` 拥有 React 组合 API、受控/非受控协议、稳定 ID 和原生事件组合。
+- `dialog/focus-management.ts` 是内部浏览器适配层。每个 `Document` 维护一个模态栈，只有栈顶处理 Escape 和焦点约束；打开时将 portal 同级背景设为 `inert`/`aria-hidden` 并锁定滚动，关闭时恢复原值和触发器焦点。
+- Portal 在服务端和水合首帧均不读取或输出浏览器 DOM，挂载 effect 后再创建 portal，因此 `defaultOpen` 也不会造成服务端/客户端首帧不一致。
+- 包不包含 CSS、产品文案、动作布局和业务按钮。样式契约是原生 props、`className`、ref 与 `data-state`，避免消费者依赖私有 DOM 选择器。
+

+

+3. 每迁移一个产品，运行其键盘、焦点、SSR 与视觉回归，并用可回滚的独立提交移除对应旧监听器和 focus workaround。三个产品都稳定后再将旧组件标记 deprecated。
+4. 至少经历一个稳定发布周期后删除旧组件和兼容适配层。若要新增关闭动画，变化应局限在 Portal/Content 的 presence 生命周期；公开状态协议、焦点层栈和产品内容边界保持不变。

+function focusInside(layer: DialogLayer, preferred?: HTMLElement | null) {
+  if (preferred?.isConnected && layer.content.contains(preferred)) {
+    focusWithoutScrolling(preferred)
+    return
+  }

+function handleKeyDown(state: DocumentState, event: KeyboardEvent) {
+  const topLayer = getTopLayer(state)
+  if (!topLayer) return
+
+  if (event.key === 'Escape') {
+    topLayer.onEscapeKeyDown?.(event)
+    if (event.defaultPrevented) return

+    event.preventDefault()
+    topLayer.onDismiss()
+    return
+  }

+  if (event.key !== 'Tab') return

+  const tabbable = getTabbableElements(topLayer.content)
+  if (tabbable.length === 0) {
+    event.preventDefault()
+    focusWithoutScrolling(topLayer.content)
+    return
+  }

+  const activeElement = state.document.activeElement
+  const first = tabbable[0]
+  const last = tabbable[tabbable.length - 1]

+  } else if (
+    !event.shiftKey &&
+    (!focusIsInside || activeTabbableIndex === -1 || activeElement === last)
+  ) {
+    event.preventDefault()
+    focusWithoutScrolling(first)
+  }

+  const topLayer = getTopLayer(state)
+  const target = event.target
+  if (!topLayer || !(target instanceof HTMLElement)) return

+  if (topLayer.content.contains(target)) {
+    state.lastFocused = target
+    return
+  }
+
+  focusInside(topLayer, state.lastFocused)
+}

+    bodyOverflow: document.body.style.overflow,
+    document,
+    lastFocused: null,
+    layers: [],
+    pendingRestore: [],
+    restoreScheduled: false,
+    siblingSnapshots: [],
+  }
+
+  document.addEventListener('keydown', (event) => handleKeyDown(state, event))
+  document.addEventListener('focusin', (event) => handleFocusIn(state, event))
+  states.set(document, state)
+  return state

+function scheduleFocusRestoration(state: DocumentState) {
+  if (state.restoreScheduled) return
+  state.restoreScheduled = true
+
+  queueMicrotask(() => {
+    state.restoreScheduled = false
+    const topLayer = getTopLayer(state)
+    const candidate = state.pendingRestore
+      .splice(0)
+      .reverse()
+      .find(
+        (element): element is HTMLElement =>
+          element !== null &&
+          element.isConnected &&
+          (!topLayer || topLayer.content.contains(element)),
+      )
+
+    if (candidate) {
+      focusWithoutScrolling(candidate)
+    } else if (topLayer && !topLayer.content.contains(state.document.activeElement)) {
+      focusInside(topLayer)
+    }
+  })
+}

+export function activateDialogLayer(layer: DialogLayer) {
+  const document = layer.content.ownerDocument
+  const state = states.get(document) ?? createDocumentState(document)
+
+  if (state.layers.length === 0) {
+    state.bodyOverflow = document.body.style.overflow
+  }
+  state.layers.push(layer)
+  state.lastFocused = null
+  syncModalEnvironment(state)
+  focusInside(layer, layer.initialFocus)
+
+  return () => {
+    const index = state.layers.indexOf(layer)
+    if (index === -1) return
+
+    state.layers.splice(index, 1)
+    state.pendingRestore.push(layer.restoreFocus)
+    state.lastFocused = null
+    syncModalEnvironment(state)
+    scheduleFocusRestoration(state)
+  }
+}

+  if (!content) return false
+  const state = states.get(content.ownerDocument)
+  return getTopLayer(state)?.content === content

+# Vite feature flags
+
+This package exposes a deliberately selected subset of a server-owned JSON file
+to browser code through `virtual:feature-flags`. It does not treat flags as an
+authorization boundary: privileged behavior must still be enforced by the
+server.
+
+## Setup
+
+```ts
+// vite.config.ts
+import { featureFlags } from '@frontend-architect-eval/feature-flags'
+
+export default {
+  plugins: [
+    featureFlags({
+      source: new URL('./flags.json', import.meta.url),
+      expose: ['checkoutV2', 'theme'],
+    }),
+  ],
+}
+```
+
+Only names in `expose` are serialized. Keeping credentials next to flags is not
+recommended, but a field omitted from `expose` cannot enter the generated module
+or its source map. Exposed values are restricted to booleans, finite numbers,
+and strings. Invalid JSON, missing names, and invalid values fail startup or the
+build with the source path, affected option or flag, and a corrective action.
+
+Add the `./virtual` type entry to the consumer's `tsconfig.json`:
+
+```json
+{
+  "compilerOptions": {
+    "types": ["@frontend-architect-eval/feature-flags/virtual"]
+  }
+}
+```
+
+Then declare the application-owned schema in a `.d.ts` file:
+
+```ts
+declare module 'virtual:feature-flags' {
+  interface FeatureFlags {
+    readonly checkoutV2: boolean
+    readonly theme: 'dark' | 'light'
+  }
+}
+```
+
+Consumers now get exact property and value types:
+
+```ts
+import { flags } from 'virtual:feature-flags'
+
+if (flags.checkoutV2) {
+  // ...
+}
+```
+
+`FeatureFlagsOptions` and `FeatureFlagValue` are public types from the package
+root. `FeatureFlags` and `flags` are public from the `./virtual` type entry. All
+other modules are private because the package `exports` map exposes only `.` and
+`./virtual`; `./virtual` points to an empty runtime module solely so TypeScript
+and package resolvers can find its ambient declaration. Application runtime code
+must import `virtual:feature-flags`, which Vite resolves.
+
+## Lifecycle, caching, and source maps
+
+The same `load` implementation generates development, SSR-development, and
+production-build modules. The parsed result is cached per plugin instance after
+Vite resolves the project root. The source JSON is registered with Vite's
+watcher; a change clears that cache and invalidates the virtual module, so the
+next HMR or SSR load reads and validates a fresh snapshot. There is no shared
+process cache and therefore no cross-project or cross-build flag leakage.
+
+The plugin returns a source map for its generated module. Its `sourcesContent`
+contains only that generated, allowlisted module—not the JSON source—so private
+fields cannot be copied into client source maps. The virtual source identity is
+stable across development and build.
+
+## Verification and releases
+
+Run `npm run check` from the repository root. It builds declarations and source
+maps, type-checks a consumer, executes a real Vite production build, exercises a
+real development server and JSON-file HMR, verifies actionable diagnostics, and
+installs the packed tarball in a temporary consumer. The build check also scans
+JavaScript and source maps for a non-exposed sentinel secret.
+
+`node --test tests/plugin-lifecycle.test.mjs` provides a focused lifecycle check
+for virtual-module invalidation and verifies the plugin-level source map itself.
+
+The public contract is the plugin options, exported root types, the virtual
+module's named `flags` export, supported primitive values, diagnostics, and HMR
+refresh behavior. Additive option fields and new diagnostics are normally minor
+changes. Renaming an export or virtual ID, removing a value kind, changing path
+resolution, making validation stricter for previously valid input, or changing
+the `FeatureFlags` augmentation contract requires a major release and migration
+notes. Deprecate old options with a replacement and removal release before
+deleting them. Use a prerelease and run the packed-consumer checks when changing
+Vite's supported peer range or the generated-module format.
