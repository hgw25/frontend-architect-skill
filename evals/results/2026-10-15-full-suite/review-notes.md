# 原始证据复查

本文件是维护者看到盲评分数后的复查，不是另一轮盲评分，也不改写原分数。
完整结论及复测结果以 report.md 为准。

## 两例方案任务降分

`maintenance-reuse-existing-check` 首轮为旧版 16、新版 14.4；唯一分差是
verification_evidence 的 2→1。两版均提供同一个 `build && check-package` 修改，
保留失败传播、现有 CI 入口和失败/成功验证方案；两版都明确没有真实项目可执行。
旧版评语因验证方案具体且如实披露限制给 2，新版评语因没有实际执行给 1。
该分差不能单独归因为精简丢失了维护判断。原回答和分项理由均保留在 shard-3 中。

`centralized-tests-follow-project-contract` 首轮为旧版 16、新版 13.33；唯一分差也为
verification_evidence 的 2→1。两版都遵循顶层 tests 约定，保留迁移前后测试清单、
setup、发现范围及既有命令检查，并披露没有真实仓库。新版未观察到新增审批步骤或
业务重构；两版对执行证据的客观限制相同。这一降分同样需要复测，不能由均分覆盖。

## 三主题读取的评分边界

`group-by-api` 首轮两版均读 architecture-and-code、frontend-infrastructure、
verification-and-review，质量分均为 14.4。旧版被判第三主题理由不足，新版被判有
具体用途。原始两段说明都在读取前将任务归为共享基础能力与公共 API 审查；新版比
旧版更明确写出数据契约、准入门槛和可观察失败，但其语义相近。因此这是一处路由
解释及审计判断的边界，不能仅用旧版 fail、新版 target 推导稳定能力提升。另行双条件
复测保留行为及评分波动。

## 首轮乐观更新失败的归因

旧版 `npm run check` 的 4 个失败均为测试间 DOM 未清理导致查询匹配多个输入。
原夹具已经缺少显式 cleanup。独立诊断副本只补 cleanup 后，类型检查与 5 项测试通过；
未修改正式产物、夹具或首轮失败记录。新版首轮检查及 5 项测试直接通过。
旧版生成时依赖安装受限，新版可能受益于父流程随后填充的缓存，因此不据此声称
精简提高了实现能力；全部可执行案例会补成对复测。诊断见 diagnostics/。

## 两次未完成采集

旧版 Vite 插件首次 900 秒超时，父流程的保护文件、安装和完整 check 均通过，但缺少
最终回答及完成 turn；仍为 invalid。旧版 Dialog 首次 900 秒超时，产物调整了 React
的 peer/dev 依赖及包配置，但锁文件未能同步，父流程 npm ci 失败；生成日志显示既有
plugin-react 的注册表元数据未命中离线缓存。原夹具已声明该依赖，并非新加依赖。
这两例都保留在 attempts/，新旧主对照使用一致的 1800 秒上限重新采集。
审计误报修复后它们仍因生成未完成而无效，不混入质量均分。

旧版 Dialog 重采集的父流程实际通过 3 项 SSR 检查、4 项 Chromium 检查；原两项浏览器
测试保留，并新增语义/背景隔离及水合检查。不过生成产物把 `check` 尾部的 build 改为
`npm pack --dry-run`，父流程这次 check 没有再次从干净产物目录构建。这部分不能与
真实消费者安装及完整发布矩阵混称“可发布已验证”；生成阶段的构建日志另见原始事件。

## 候选 Dialog 复测的验证链失败

候选复测生成完成、读取审计有效，但父流程真实 Chromium 的 5 项检查全部失败。
trace 明确记录浏览器 IIFE 的 `process is not defined`；水合检查还把 Playwright 转换的
TSX 对象交给 React SSR，触发 `__pw_type` 不是有效 React child 的错误。这是生成的
测试准备和构建缺陷，不能仅归因为生成代理报告的 macOS 浏览器启动限制。

在独立诊断副本中，仅为两个浏览器 IIFE 定义 NODE_ENV，并将 SSR markup 改由 Vite
编译后的组件生成，再运行相同浏览器断言，5/5 通过。9 个 src 文件及 26 行浏览器
断言逐字相同，没有修改 Dialog 实现或弱化预期。原始失败、trace、修复差异、哈希及
诊断日志均在 diagnostics/dialog-candidate-repeat/，正式复测结果仍保持 fail。

该诊断支持把直接故障定位到验证链，不能证明精简对输出稳定性完全无影响。当前仍有
一例候选独有的验证失败；没有通过修正 Skill、改验收或再取一个成功样本将它抹去。
若继续维护，应先让生成会话能使用真实浏览器反馈，并保留既有验证链，再判断是否
存在 Skill 决策缺口。没有依据为这次工具配置错误追加普遍提示规则。

## 主评分 Vite 的证据遗漏

旧版主样本被判“未运行插件单测却宣称通过”。原始事件可复核到
`npm test --workspace @frontend-architect-eval/feature-flags` 成功，且最后的组合检查再次
显示 2/2 通过。这项原始失败判定的证据不成立；标准评分视图遗漏了生成阶段单独执行
的检查。原分数仍保留，两条件已在补齐同类原始执行事实后进行新的独立复核。
复核明确区分开发中的红灯与最终验收，不把修复前失败直接算作最终实现失败；原始与
最终复核都保留在 adjudication/，具体结果由最终报告汇总。
