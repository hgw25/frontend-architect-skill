## 结论

选择 **FLIP 作为重排动画层级，并用 Web Animations API（WAAPI）执行可中断动画**。不新增动画库。

FLIP 负责解释卡片从旧位置到新位置的空间关系；WAAPI 只是播放与取消手段，不拥有列表顺序。无动画路径同时作为 `prefers-reduced-motion` 和能力降级方案。

| 方案 | 判断 |
| --- | --- |
| 无动画 | 保留为降级路径，但普通模式下连续换位会缺少空间连续性 |
| CSS transition | 适合拖起阴影、透明度等局部状态；不能自行识别 DOM 重排，手工计算位移后本质上仍是 FLIP |
| View Transitions API | 快照式状态切换更适合低频页面/视图变化，不适合逐帧附近的连续重排、反向打断和自动滚动 |
| FLIP | **采用**。可以根据真实几何位置处理变高卡片、双向移动和滚动容器 |
| 动画库 | 当前仓库没有依赖依据，不为这一能力新增；若实际拖拽库已内置可中断的 layout animation，应复用其 FLIP 等价能力，避免两个动画所有者 |

## 交互与状态边界

列表顺序是唯一业务真相，动画只读取几何信息：

1. 拖拽中的卡片直接跟随指针，不做缓动，避免输入滞后；建议使用独立 drag overlay。
2. 碰撞检测得到的新索引只有发生变化时才请求重排。
3. 每个 animation frame 最多处理一次重排；同一帧多次 pointer move 只保留最新目标索引。
4. 重排事务依次执行：

   - 按稳定 `itemId` 读取所有可见卡片当前的视觉位置，即 First。
   - 记录位置后取消尚未结束的旧动画。
   - 立即更新顺序并让 DOM 达到最终布局。
   - 在框架的布局提交阶段批量读取 Last。
   - 对每张未拖拽卡片计算 `First - Last`，从该 `translate` 动画到 `none`。

5. 新输入打断动画时，First 必须取元素当时屏幕上的实际位置，再取消旧动画。这样反向拖动或连续跨越多个位置不会先跳回旧终点。
6. drop、Escape、拖拽项被移除、组件卸载时，统一取消 animation handles 并清理临时样式。
7. 若顺序需要持久化，只在 drop 后提交最终顺序；hover 阶段的临时排序和动画不触发多次远端写入。

建议使用约 `140ms`、无延迟的 ease-out 位移动画，只动画 `transform`，不缩放卡片内容。卡片必须使用稳定 ID，不能以数组索引作为渲染 key。

为防止 transform 争用，布局节点的 transform 只归重排动画所有；卡片自身的 hover、选中等视觉效果放在内层元素。若拖拽库已经控制同一节点的 transform，则必须改用它提供的排序动画入口，不能叠加自定义 FLIP。

## 滚动容器

几何位置使用滚动内容坐标，而不是裸 viewport 坐标：

```text
x = itemRect.left - scrollerRect.left + scrollLeft
y = itemRect.top  - scrollerRect.top  + scrollTop
```

这能避免自动滚动时所有卡片被误判为发生了重排。

- 自动滚动和碰撞检测仍由拖拽层负责。
- drag overlay 根据 pointer 和 scroll 事件在同一个 rAF 调度器中更新。
- 只对当前挂载且 First、Last 都存在的稳定 ID 做 FLIP。
- resize 或容器尺寸变化时取消当前动画；下一次实际重排重新测量，不使用过期矩形。
- 首版边界限定为一个明确的滚动容器。嵌套滚动区、带缩放 transform 的祖先或虚拟列表需要与对应库的坐标系统单独集成。

位置使用 `{x, y}` 实际测量而非“索引 × 固定高度”，因此变高卡片以及未来改成网格时不需要重写状态模型。

## Reduced motion 与可访问性

`prefers-reduced-motion: reduce` 时：

- 顺序仍立即更新；
- 不执行 FLIP、拖起缩放、回弹或平滑滚动；
- 若偏好在动画中途改变，立刻取消全部动画并显示最终布局；
- 卡片直接跟随指针属于直接操作反馈，可以保留，但不添加惯性或补间。

JS 侧需要通过 `matchMedia` 决定是否创建动画并清理监听；CSS media query 作为样式层兜底。

拖拽还应提供键盘或“上移/下移”操作，调用同一个 `move(itemId, targetIndex)` 顺序动作。焦点继续停留在同一稳定 ID 上，并通过 live region 简短播报新位置。

## 验证方案

使用项目已有的真实浏览器测试工具，不因该功能单独引入测试框架。

重点自动化场景：

- 在前一轮 `140ms` 动画结束前连续跨越多个位置，最终 DOM 顺序准确。
- 动画中立即反向拖动，卡片从当前视觉位置继续，没有闪回。
- 滚动容器自动滚动时继续换位，drag overlay 保持在指针下，未换位卡片不产生滚动补偿动画。
- drop 前最后一次 pointer move 尚未处理时，最终目标仍被应用。
- Escape、卸载和拖拽项被删除后，没有遗留 transform 或动画句柄。
- 启动即 reduced motion，以及动画途中切换 reduced motion，均直接进入正确终态。
- 键盘重排保持焦点，并产生正确播报。

真实浏览器性能检查使用产品支持矩阵和代表性列表规模：

- 录制快速拖拽与自动滚动的 Performance trace。
- 确认 pointer move 没有逐事件触发布局，最多每帧一次重排事务。
- DOM 读取批量发生在写入之前，不出现按卡片交错读写造成的 layout thrashing。
- 动画帧只有 transform 合成工作，没有持续 layout/paint。
- 在目标设备刷新率下不连续丢帧；若不达标，先依据 trace 缩小测量范围，而不是直接引入动画库。
