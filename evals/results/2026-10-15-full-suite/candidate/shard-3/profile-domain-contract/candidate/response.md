建议采用一条明确的用户域链路：`userId` 负责用户主页，`developerLogin` 只负责开发者署名。两者没有映射时，绝不能通过字符串猜测或拼接跳转。

## 最小页面方案

路由定义为：

```text
/users/:userId
```

- 路由参数始终是 `userId`。
- 账户菜单中的“个人主页”使用当前登录态提供的 `userId`。
- 若当前登录态没有 `userId`，这是接口契约缺口，需要认证响应补充该字段或提供明确的当前用户接口，不能拿用户名或 `developerLogin` 代替。
- GitHub 只作为视觉参考：桌面端左侧 profile、右侧 applications；窄屏改为单列。只展示现有响应字段，不为了模仿 GitHub 新造关注数、贡献图等产品能力。
- 沿用项目已有组件、颜色和断点；不引入新的 UI 或数据依赖。

## 数据流

```text
route.params.userId
  → 用户主页的数据查询边界
  → GET /users/{userId}（携带现有登录凭证）
  → { profile, applications }
  → profile 区域 + applications 列表
```

关键规则：

1. 页面只请求这个聚合接口，不再分别拉取 profile 和 applications。
2. `applications` 是服务端根据查看者授权后返回的完整可见集合。前端不得根据旧注释再次过滤，也不得用 `isSelf` 推断权限。
3. `isSelf = routeUserId === sessionUserId` 只能用于文案或本人操作的展示，不能承担授权。
4. 应用列表直接呈现服务端结果；只有现有响应确实包含可见性字段时，才显示“私有”标记。
5. 页面覆盖 loading、失败/重试、空列表和成功状态；切换 `userId` 时不能让旧请求覆盖新页面。

由于同一 URL 对不同查看者可能返回不同数据，缓存必须按身份隔离。优先复用项目现有查询层：

```text
query key = user-profile + userId + viewerKey
viewerKey = 当前 userId 或 anonymous
```

不要把 token 放入 key。如果项目在登录、退出和切换账号时会整体清空查询缓存，也可以沿用该机制。必须验收“本人看过私有应用后退出或切换账号”的场景，避免私有结果从缓存泄漏给下一位查看者。

旧生成注释应在 OpenAPI/接口描述源头改为类似：

> applications 包含当前查看者有权查看的应用；本人可包含公开和私有应用。

随后走项目原有生成流程。不要只手改生成文件。产品负责人确认的当前行为高于旧生成注释，前端实现不应继续采用“仅公开”的旧语义。

## 作者入口

`developerLogin` 不能用于 `/users/:userId`。

当前最小处理是：

- 若项目已有以 `developerLogin` 为键的开发者详情页，则作者名链接到那个开发者域路由。
- 若没有，则作者名显示为普通文本，不提供用户主页链接。
- 不新增客户端搜索、逐作者请求或字符串匹配来猜测用户身份。

如果产品以后要求“从作者进入用户主页”，服务端需要提供显式、可空的关联，例如 `author.userId`。因为用户和开发者是两个身份体系，该映射应由服务端领域契约拥有。

## 实现顺序

1. 确认并修正接口描述源，重新生成类型；保留 `profile`、`applications` 的原字段名。
2. 在现有 API/query 层增加 `getUserProfile(userId)`，明确查看者相关缓存策略和路由切换时的旧结果处理。
3. 注册 `/users/:userId`，先接通“路由—请求—基本渲染”的完整链路。
4. 完成 GitHub 风格的 profile 与 applications 布局，以及 loading、error、empty 状态。
5. 从账户菜单增加本人主页入口；按上述规则处理 `developerLogin` 作者署名。
6. 添加身份矩阵测试并进行浏览器验收。

不建议在第一版加入编辑资料、分页、筛选、关注关系或作者—用户解析服务。

## 验收方式

接口与页面联合验收：

| 场景 | 预期 |
|---|---|
| 本人访问自己的 `userId` | 页面完整显示接口返回的公开和私有应用，不被前端过滤 |
| 其他登录用户访问同一 `userId` | 只显示服务端返回的可见应用 |
| 匿名访问（若接口允许） | 只显示服务端允许的内容；若接口要求登录，则按既有 401 流程处理 |
| 本人访问后退出或切换账号 | 相同路由不会复用包含私有应用的旧缓存 |
| 快速从用户 A 切换到用户 B | A 的迟到响应不会覆盖 B 的页面 |
| 点击账户菜单“个人主页” | URL 和请求使用同一个当前用户 `userId` |
| 点击或查看作者署名 | 不会把 `developerLogin` 当作 `userId`；无开发者路由时不可点击 |
| 应用为空、请求失败、用户不存在 | 分别出现明确空状态、可重试错误和项目既有的不存在页面 |
| 响应式与可访问性 | 手机单列、长文本不溢出；链接可键盘访问、焦点可见、头像有合适替代文本 |

自动化测试至少覆盖查询身份隔离、本人/他人两种响应渲染、路由快速切换和作者不误跳用户主页；再用真实浏览器检查直达 URL、刷新、后退/前进、窄屏布局及退出后的缓存行为。
