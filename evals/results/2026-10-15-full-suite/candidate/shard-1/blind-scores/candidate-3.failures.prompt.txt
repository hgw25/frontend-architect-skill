## 状态所有权

唯一的文档真相放在 `EditorSession` 内，由纯 reducer 更新：

```ts
type EditorState = {
  document: DocumentNode
  selection: ModelSelection | null
  history: HistoryState
  revision: number
}

type ModelSelection = {
  anchor: { nodeId: string; offset: number }
  focus: { nodeId: string; offset: number }
  affinity?: "forward" | "backward"
}
```

关键约束：

- `DocumentNode` 是普通可序列化数据，节点使用稳定 ID。
- `Selection` 保存模型位置，不保存 `Range`、`Node` 等 DOM 对象；是否折叠、方向等可推导值不重复存储。
- `HistoryState` 由 reducer 独占，DOM adapter 和协作控制器都不能直接改它。
- `CollaborationController` 只拥有连接状态、协议 revision、未确认操作和重连计时器，不拥有文档副本。
- DOM binding 只拥有监听器、observer 和 DOM 到模型位置的映射缓存，不拥有编辑内容。
- UI 可以组合出 `{editorState, connectionState}` 快照，但不能形成第二个可写 store。

推荐 reducer 入口：

```ts
type EditorCommand =
  | { type: "apply-local"; transaction: Transaction }
  | { type: "apply-remote"; transaction: Transaction; revision: number }
  | { type: "set-selection"; selection: ModelSelection | null }
  | { type: "undo" }
  | { type: "redo" }
  | { type: "reset"; document: DocumentNode; revision: number }

type TransitionResult = {
  state: EditorState
  outbound: readonly Transaction[]
}
```

Reducer 可以描述需要发送的本地 transaction，但不能直接访问 WebSocket 或 DOM；`EditorSession` 在提交新状态后执行 `outbound`。

## Selection 与 history

Selection 分为三层：

1. `ModelSelection`：编辑器状态中的权威表示。
2. `DOM Selection/Range`：浏览器瞬时投影。
3. 远端用户光标：presence 数据，不写入本地 selection 或 history。

每次文档 transaction 都通过纯函数映射 selection：

```ts
mapSelection(selection, transaction): ModelSelection | null
```

目标节点被删除时，按编辑器规则落到最近合法位置，而不是保留失效 DOM 引用。

History 保存可逆 transaction 或 inverse operation，不保存 HTML/DOM 快照。规则应为：

- 连续输入可以按用户意图分组。
- 光标移动不单独产生 undo 项。
- IME composition 作为一个历史单元提交。
- 新本地编辑清空 redo。
- 远端编辑更新当前文档，并映射已有 undo/redo 操作。
- 协作模式下，undo 是“提交一个本地逆操作”，不是把共享文档回滚到旧快照。

最后一点通常依赖编辑引擎的 OT/CRDT 能力；不要自行拼一个仅按数组下标回退的协作 history。

## DOM 订阅

`createDOMBinding(root, session)` 使用闭包，返回幂等清理函数：

```ts
type DOMBinding = {
  render(snapshot: Readonly<EditorState>): void
  dispose(): void
}
```

它负责：

- 注册并移除 `beforeinput`、`selectionchange`、composition、paste 等监听器。
- 对 document 级 `selectionchange` 过滤不属于当前根节点的事件。
- 把 DOM 事件翻译成编辑命令。
- 把模型 selection 投影为 DOM Range。
- 在 composition 期间保留浏览器的临时输入状态，在 composition end 时形成一个 transaction。
- 如确实需要 `MutationObserver`，它用于发现外部 DOM 改写或兼容性回退，不把 DOM 反向升级为文档真相。

应防止“模型渲染 DOM → selectionchange → 再次派发”的反馈环，但这个标记只属于 binding，不进入领域状态。

## 协作状态机与竞态

建议使用判别联合或显式状态机：

```text
idle → connecting → syncing → online
          │            │         │
          └────────→ reconnecting ┘
任何非终态 → fatal
任何非终态 → closed
```

主要策略：

- `syncing` 完成前默认只读。离线编辑若是明确产品需求，再增加 outbox、重放和 rebase，而不是默默接受可能丢失的修改。
- 每个本地操作携带 `clientOpId`、`baseRevision`；发送保持顺序。
- 服务端按稳定操作 ID 保证重试幂等；网络超时不等于写入失败。
- ack 只能确认对应操作，不能用“最后返回的请求”猜测。
- 远端 revision 出现缺口时暂停应用并请求补齐或全量重同步。
- 所有文档事件进入同一个串行 dispatch 队列，避免 DOM、ack 和远端消息同时修改状态。
- 每次 connect/reconnect 生成 `connectionGeneration`。旧 socket 的成功、失败和 `finally` 回调都必须验证 generation，不能覆盖新连接状态。
- Abort/close 用于节省资源；generation/revision 检查才负责阻止过期结果发布。

协作算法本身应由既有后端协议或成熟 OT/CRDT provider 决定。一个泛化的 `CollaborationAdapter` 只能隐藏传输差异，不能伪造服务端排序、冲突合并或幂等保证。

## 序列化边界

持久化和网络交换只使用带版本的普通数据：

```ts
type SerializedDocument = {
  schemaVersion: number
  document: DocumentNode
  revision?: number
}
```

具体规则：

- `serialize`、`deserialize`、schema migration 是纯函数。
- 外部载入的数据在边界校验一次；内部 reducer 依赖已验证契约。
- HTML 不是权威存储格式。导入 HTML 必须经过解析和净化，导出 HTML 是派生能力。
- 纯文本是有损视图：明确段落、换行、列表、图片替代文本等规则，不支持从纯文本无损恢复富文本。
- selection 可作为独立的会话恢复数据保存，但载入后必须针对当前文档 revision 重新映射或丢弃。
- history 默认不持久化，也不跨协作者传输；若需要崩溃恢复，应作为单独协议设计。
- DOM 节点、connection、AbortController、timer、listener 和类实例永不序列化。

## 生命周期与销毁

`EditorSession` 是组合根，但只负责协调：

```ts
class EditorSession {
  attach(root: HTMLElement): () => void
  connect(adapter: CollaborationAdapter): void
  dispatch(command: EditorCommand): void
  subscribe(listener: Listener): () => void
  destroy(): void
}
```

`destroy()` 必须幂等，并形成终态：

1. 标记 session 已销毁并递增 generation。
2. 移除 DOM listeners、observer 和框架订阅。
3. 取消握手、重连 timer 和待发布回调。
4. 释放 session 独占的 socket/provider。
5. 若连接是共享借用的，只 unsubscribe，不关闭共享资源。
6. 清空 subscriber 和 DOM 引用，避免节点被闭包长期持有。
7. 丢弃后续 DOM、网络和 ack 事件；销毁后 `dispatch/connect/attach` 明确抛错或返回失败，不能静默复活。

切换文档身份时，应按一次“资源替换”处理：使旧 generation 失效、断开旧协作订阅、清空旧 history，再载入新文档。不能让旧文档的延迟 ack 写入新文档。

## 最重要的验证

- 纯函数：序列化往返、schema migration、纯文本 fixtures、节点删除后的 selection 映射。
- Reducer：输入→撤销→远端编辑→重做，以及 composition 分组。
- 状态机：旧连接在新连接成功后才报错、revision 缺口、重复 ack、重连重发。
- 浏览器：跨节点 selection、IME、粘贴、外部 DOM 干扰、重复 attach/dispose。
- 销毁：销毁后的 DOM 和网络回调均不能发布状态；共享连接不会被单个编辑器关闭。

一个现实的后续变化——把 WebSocket 换成共享 Worker 或 CRDT provider——只需替换 `CollaborationAdapter` 和连接控制器；document reducer、纯文本转换和 DOM binding 不应随之改写。这是该边界是否足够清晰的核心检验。

## 数据与序列化契约

传给客户端的不是 Shopify 原始对象，而是窄 DTO，例如：

```ts
type MoneyView = {
  amount: string;
  currencyCode: string;
};

type ProductPurchaseView = {
  id: string;
  handle: string;
  pricingContextKey: string;
  options: Array<{
    id: string;
    name: string;
    values: string[];
  }>;
  variants: Array<{
    id: string;
    selectedOptions: Array<{ name: string; value: string }>;
    availableForSale: boolean;
    price: MoneyView;
  }>;
};
```

约束：

- 金额保留 Shopify 返回的十进制字符串和实际 `currencyCode`，不要穿过边界传 `Decimal`、`BigInt` 或自行浮点换算。
- 日期转 ISO 字符串；不传 `Map`、`Set`、类实例、函数、SDK response 或 Error 对象。
- 只选取浏览器真正需要的字段，不传成本价、后台字段、请求头或凭据。
- 商品 HTML 描述属于外部输入：优先转换为受控结构；必须使用 HTML 时，在服务端按项目既有方案净化。
- variant ID 是不可信客户端输入。加购时服务端重新确认它属于当前商品、仍可售且数量合法，不能信任客户端价格。
- 若 variant 数量实际导致 RSC payload 过大，再把“按选择查询 variant”作为后续优化；没有测量前不引入额外请求机制。

客户端只保存不可派生状态，如所选 option 和提交状态；价格、可售性和 variant 从最新 DTO 推导。用 `productId + pricingContextKey` 作为交互岛的 `key`，避免切换商品或市场后保留旧货币状态。

## SEO 与用户货币

服务端按以下优先级解析定价上下文：

1. 已校验、受支持的货币/市场 cookie；
2. 项目已有地区或市场判定；
3. 店铺默认市场。

货币必须映射到 Shopify 支持的市场上下文，以 Shopify 返回的真实币种为准，不接受客户端传入的任意汇率或价格。

读取 cookie 意味着该商品页面通常是请求时动态渲染；这并不妨碍 SEO。核心商品 HTML、`generateMetadata` 和 JSON-LD 仍在服务端生成。搜索爬虫无用户偏好时看到稳定的默认市场版本，canonical 保持为商品 URL，不为 cookie 货币制造重复 URL。

`generateMetadata` 与页面商品读取应使用项目版本支持的请求级去重，避免同一请求重复访问 Shopify。JSON-LD 中使用该次服务端请求的实际价格和币种，并安全序列化。

## Suspense 和错误恢复

- 商品主体是 SEO 和购买的关键内容：服务端等待商品后再决定渲染、`notFound()` 或抛给路由 `error.tsx`。
- `loading.tsx` 可用于客户端导航时的整页骨架，但不能替代最终的可索引商品 HTML。
- 推荐商品是非关键内容：独立 `Suspense`，fallback 保留稳定高度，避免布局跳动。
- Shopify 返回“商品不存在”时进入 `not-found.tsx`；网络或上游故障不能伪装成 404。
- 推荐请求的已知上游失败可映射为明确的“暂时无法加载推荐”状态和重试按钮；程序错误继续抛出，不吞成空数组。
- `error.tsx` 提供 `reset()` 重试，并保留返回目录或搜索的路径。
- 加购业务拒绝返回有类型的表单状态；焦点保留在购买区域，并通过 `aria-live` 宣告结果。
- 提交期间禁用重复加购。若请求超时而结果未知，应重新读取权威购物车后对账；不能把超时直接视为未加购并盲目重试。
- 日志可记录操作、商品/variant 标识和错误类别，但不得记录凭据、完整 cookie 或敏感请求体。

|---|---|---|---|
| 公共商品详情 | 店铺 + handle/ID + country/market + currency + language | 服务端跨请求缓存；TTL 由业务新鲜度确定 | Shopify webhook、后台商品更新；保留 TTL 兜底 |

| 货币偏好 | 当前请求/cookie | 不进入公共数据缓存 | 用户切换 |
| 购物车 | 用户/会话 | `no-store` 或项目既有会话缓存 | 每次购物车 mutation 后刷新权威状态 |

两个缓存层必须区分：

- 请求级去重：供 `generateMetadata` 和页面在同一次渲染中复用。
- 跨请求数据缓存：只缓存明确属于公共范围的 Shopify 结果。

如果价格受客户身份、B2B 合同或登录状态影响，则不得仅按币种缓存，应改为会话级或 `no-store`。添加购物车通常不代表库存已经变化，不应无条件清掉整个商品目录缓存。

失效由实际修改数据的一方负责。Shopify webhook 应验证签名后，根据 handle/ID 失效商品和推荐 tag；初期无法可靠映射 ID 与 handle 时，可以失效店铺级 catalog tag，之后再基于实际压力细化。具体采用 `revalidateTag`、`updateTag`、`unstable_cache` 或 `use cache`，需以仓库锁定的 Next.js 版本为准，不能混用不同版本语义。

+export function isSupportedLocale(value: string | null): value is SupportedLocale {
+  return value !== null && supportedLocales.some((locale) => locale === value)
+}
+
+export function createI18n(locale: SupportedLocale) {
+  const messages = catalogs[locale]
+  const pluralRules = new Intl.PluralRules(locale)
+  const numberFormatter = new Intl.NumberFormat(locale)
+  const currencyFormatter = new Intl.NumberFormat(locale, {
+    style: 'currency',
+    currency: messages.currency,
+  })
+
+  return {
+    messages,
+    formatResultCount(count: number) {
+      const plural = pluralRules.select(count) === 'one' ? 'one' : 'other'
+      return messages.resultCount[plural].replace(
+        '{count}',
+        numberFormatter.format(count),
+      )
+    },
+    formatPage(page: number) {
+      return messages.page.replace('{page}', numberFormatter.format(page))
+    },

+# Headless Dialog primitive
+
+This package centralizes the modal behavior shared by the three React products while leaving product copy, actions, layout, and visual styling in each consumer.
+
+## Public API
+
+Import only from the package root:
+
+```tsx
+import { Dialog } from '@fixture/headless-dialog'
+
+<Dialog.Root defaultOpen={false} onOpenChange={(open, details) => {}}>
+  <Dialog.Trigger className="button">Edit profile</Dialog.Trigger>
+  <Dialog.Portal>
+    <Dialog.Overlay className="overlay">
+      <Dialog.Content className="panel">
+        <Dialog.Title>Edit profile</Dialog.Title>
+        <Dialog.Description>Update your public information.</Dialog.Description>
+        {/* Product fields and actions belong here. */}
+        <Dialog.Close>Cancel</Dialog.Close>
+      </Dialog.Content>
+    </Dialog.Overlay>
+  </Dialog.Portal>
+</Dialog.Root>
+```
+
+`Dialog.Root` supports uncontrolled state with `defaultOpen` and controlled state with `open` plus `onOpenChange`. The change callback reports `trigger`, `close-button`, `escape-key`, or `outside-pointer` as its reason. `Dialog.Portal` accepts an optional DOM `container`; its default is `document.body`. `Dialog.Content` accepts `initialFocusRef`, `finalFocusRef`, and `restoreFocus`, in addition to normal `div` attributes. All DOM components forward refs and normal class, style, data, and event props. A consumer event handler can call `preventDefault()` to cancel the corresponding primitive behavior.
+
+Use exactly one `Dialog.Title` and `Dialog.Description` per content panel. If a visible title is not appropriate, give `Dialog.Content` an `aria-label`. The primitive owns `role="dialog"`, `aria-modal`, stable label/description IDs, focus containment, focus restoration, Escape, background isolation, and nested-layer ordering. Consumers own all text, business actions, loading policy, validation, layout, z-index policy, and animation.
+
+Named component and prop/type exports are also available from the same root entry. Internal focus and layer modules are intentionally absent from `package.json#exports`.
+
+## Runtime and package boundary
+
+The package ships ESM and declarations from `dist/package`; React and React DOM are peers so every product supplies its existing singleton runtime. It has no CSS side effect. Portal rendering is deferred until the browser has mounted, so a server render and the first hydration render agree and never access `document`. `useId` keeps semantic IDs hydration-stable.
+
+The layer registry is the only cross-instance state. It determines the top dialog and temporarily makes everything outside that dialog's DOM branch inert and hidden from the accessibility tree. Each content instance independently owns its focus listener, initial focus, Tab loop, cleanup, and restoration. This separation is what lets nested and separately controlled dialogs compose without one Escape closing several layers.
+
+## Test matrix
+
+| Contract | Evidence |
+| --- | --- |
+| Closed and initially-open portal SSR | Node `renderToString` tests; no browser globals |
+| Hydration followed by portal opening | Playwright against server-shaped HTML; console/page errors fail the test |
+| Uncontrolled open, initial focus, forward/backward Tab loop | Playwright keyboard behavior |
+| Programmatic focus escape and trigger restoration | Playwright focus assertions |
+| Accessible name, description, and modal semantics | Browser accessibility-tree assertions |
+| Escape and pointer-outside dismissal | Playwright keyboard and pointer tests |
+| Nested layers | Playwright verifies top-only Escape, parent isolation, and local restoration |
+| Controlled state and consumer class/content | Playwright controlled example |
+| Public ESM and declaration artifact | Vite library build, TypeScript declaration emit, and `npm pack --dry-run` |
+
+The supported release matrix is React 18–19 and modern browsers with `HTMLElement.inert`. Before publishing, run `npm run check` and `npm pack --dry-run` in CI on each supported React major's consumer fixture.
+
+## Three-product migration
+
+1. Publish a prerelease and add one package-level adapter in each product that maps its current modal component to the compound API. Keep product names, copy, actions, classes, analytics, and async behavior in that adapter.
+2. Migrate one low-risk dialog per product. Compare keyboard order, initial/final focus, Escape, outside-pointer policy, stacking, and screenshots in that product's real shell. Rollback is an import switch to the existing implementation.
+3. Migrate nested and controlled dialogs next. Remove product-level document key listeners and focus traps only after their replacement passes the shared browser suite plus the product journey.
+4. Migrate remaining call sites mechanically, then forbid new imports of the legacy implementations with the repository's existing lint/import-boundary tooling.
+5. After one release cycle without legacy callers, delete the three old implementations and their global listeners/styles. Promote the prerelease only after packed-artifact and React 18/19 consumer checks pass.
+
+Do not wrap arbitrary product confirmation flows, form submission, or translated button copy into this primitive. If products later need alert-dialog semantics or non-modal panels, add separate primitives rather than flags that weaken this modal contract.

+import type { KeyboardEvent as ReactKeyboardEvent } from 'react'

+const TABBABLE_SELECTOR = [
+  'a[href]',
+  'area[href]',
+  'button:not([disabled])',
+  'input:not([disabled]):not([type="hidden"])',
+  'select:not([disabled])',
+  'textarea:not([disabled])',
+  'iframe',
+  'audio[controls]',
+  'video[controls]',
+  '[contenteditable]:not([contenteditable="false"])',
+  '[tabindex]:not([tabindex="-1"])',
+].join(',')
+
+function isTabbable(element: HTMLElement) {
+  const style = window.getComputedStyle(element)
+
+  return (
+    !element.hidden &&
+    style.display !== 'none' &&
+    style.visibility !== 'hidden' &&
+    element.getClientRects().length > 0 &&
+    element.tabIndex >= 0
+  )
+}
+
+export function getTabbableElements(container: HTMLElement) {
+  return Array.from(container.querySelectorAll<HTMLElement>(TABBABLE_SELECTOR)).filter(
+    isTabbable,
+  )
+}
+
+export function focusInitialElement(
+  container: HTMLElement,
+  requestedElement?: HTMLElement | null,
+) {
+  const candidate =
+    (requestedElement && container.contains(requestedElement) ? requestedElement : null) ??
+    container.querySelector<HTMLElement>('[autofocus]') ??
+    getTabbableElements(container)[0] ??
+    container
+
+  candidate.focus({ preventScroll: true })
+  return candidate
+}
+
+export function keepTabFocusInside(
+  event: ReactKeyboardEvent,
+  container: HTMLElement,
+) {
+  if (event.key !== 'Tab') return
+
+  const tabbableElements = getTabbableElements(container)
+  if (tabbableElements.length === 0) {
+    event.preventDefault()
+    container.focus({ preventScroll: true })
+    return
+  }
+
+  const first = tabbableElements[0]
+  const last = tabbableElements[tabbableElements.length - 1]
+  const activeElement = document.activeElement
+
+  if (event.shiftKey && (activeElement === first || activeElement === container)) {
+    event.preventDefault()
+    last.focus({ preventScroll: true })
+  } else if (!event.shiftKey && activeElement === last) {
+    event.preventDefault()
+    first.focus({ preventScroll: true })
+  }
