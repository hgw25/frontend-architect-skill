## 最小重构方案

| 范围 | 处理 |
|---|---|
| 会话面板 `sheetHeight` | 删除。全高是固定布局约束，不再作为可变业务状态保存 |
| 会话面板 `heightListener` | 删除注册、回调、清理以及相关 import；不要改成空监听或常量回调 |
| WebView 中间高度补偿 | 删除高度计算、绘制补偿和触发链；WebView 直接填充头部以下的可用内容区 |
| 五个透传参数 | 从最底层声明开始，沿组件 props、类型、调用点逐层删除；不要继续传 `undefined` 或固定值 |
| 60% 停靠 | 删除对应 snap point、分支、按钮处理器、动画目标和测试夹具 |
| 全高收起动画 | 直接复用项目已有实现，不再新增一套关闭动画 |
| 公共可调高度抽屉 | 保持 API 和内部高度机制不变，避免影响仍需调高/停靠的页面 |

会话面板的交互状态应收敛为：

```text
closed ──打开──> full
full ──拖动头部──> dragging
dragging ──达到关闭条件──> 复用现有全高收起动画 ──> closed
dragging ──短拖/取消──> 回弹到 full
```

拖动位移可以继续由现有手势或动画值临时持有，但不能重新成为持久化的 `sheetHeight`。布局高度始终由全高容器决定。

实施顺序建议：

1. 先找到五个参数的声明端和最终消费端，确认均只服务旧停靠、高度监听或 WebView 补偿。
2. 将会话面板接到已有全高展开/收起路径，确保释放拖动时只有“关闭”或“回弹”两个结果。
3. 让 WebView 使用父容器布局填满剩余空间。
4. 删除 `sheetHeight`、`heightListener`、补偿逻辑及五参数的整条透传链。
5. 最后检查公共抽屉的其他调用方；其可调高度能力不应因本次清理而改变。

不建议给公共抽屉增加 `disableDocking`、`fixedSessionMode` 一类兼容开关。那会把已取消的产品状态继续留在运行路径里。将来若会话面板重新需要停靠，应明确重新选择公共可调抽屉能力，而不是依赖这次遗留的隐式参数。

## 验证计划

1. 静态与契约检查

   - 类型检查通过，证明五参数已从完整调用链移除。
   - 在会话功能范围内搜索 `sheetHeight`、`heightListener`、60% snap point 和 WebView 补偿入口，应无残留。
   - 同名机制若属于公共抽屉且仍有其他真实消费者，则应保留，不能以全仓“零结果”为目标。
   - 检查监听器数量，确认打开会话面板不会再注册高度监听。

2. 会话面板交互测试

   - 从关闭状态打开，最终只停在全高，没有短暂或稳定的 60% 状态。
   - 在头部向下拖动并达到现有关闭条件，执行已有收起动画并关闭。
   - 未达到关闭条件时释放，面板回弹到全高。
   - 拖动过程中取消手势，仍回弹到全高。
   - 回弹或关闭动画尚未完成时再次交互，不产生旧高度写回、跳到 60% 或动画结束后反向闪动。

3. WebView 布局验证

   - 分别使用短内容和可滚动长内容，检查 WebView 顶部不遮挡头部、底部可达且没有空白补偿区。
   - 面板打开期间改变视口或设备方向，WebView 随父布局调整，不依赖已删除的高度监听。
   - 检查实际边界和滚动可达性，不能只断言样式类存在。

4. 公共抽屉回归

   - 选择至少一个仍使用可调高度抽屉的页面。
   - 验证其 60% 或其他中间高度仍可进入、拖动、回弹和关闭。
   - 验证其高度回调或监听仍按原契约工作。
   - 运行该共享组件已有测试，确保此次修改没有缩窄公共 API。
