## 1. 文档与 selection：纯数据和纯函数

selection 不应保存 `Node`、`Range` 或 DOM offset。它应引用编辑器文档中的逻辑位置：

```ts
type TextPoint = {
  blockId: string
  offset: number
  affinity?: 'before' | 'after'
}

type EditorSelection =
  | { kind: 'caret'; point: TextPoint }
  | { kind: 'range'; anchor: TextPoint; focus: TextPoint }
  | { kind: 'node'; nodeId: string }
```

主要操作保持纯粹：

```ts
applyTransaction(snapshot, transaction)
mapSelection(selection, documentChange)
normalizeSelection(document, selection)
domSelectionToModel(root, nativeSelection)
modelSelectionToDom(root, selection)
```

其中前面三个属于 model；后面两个虽然计算部分可以纯化，但读取、设置真实 DOM 必须留在 DOM 适配器中。

状态所有权：

- 文档工作副本由 editor session/store 拥有，并且只能通过事务入口修改。
- selection 属于具体编辑视图，而不是共享文档。一个文档开两个编辑视图时，它们可以有不同光标。
- 远端光标是协作 presence 数据，不能混入本地 selection。
- DOM Selection 只是投影，不是第二份真相。

## 2. History：独立 Reducer

history 适合 reducer，而不是让 `Editor` 类暗中维护两个数组：

```ts
type HistoryState = {
  undo: HistoryEntry[]
  redo: HistoryEntry[]
  group?: HistoryGroup
}

type HistoryEvent =
  | { type: 'local-applied'; transaction: AppliedTransaction }
  | { type: 'remote-applied'; mapping: PositionMapping }
  | { type: 'undo' }
  | { type: 'redo' }
  | { type: 'clear' }
```

关键规则：

- 只把本地可撤销事务加入当前用户的 history。
- 远端编辑不进入本地 undo 栈，但必须映射/rebase 栈内位置。
- undo 是生成一个新的逆事务，不是直接恢复旧快照。
- 输入合并依据明确元数据，例如输入来源、时间窗口和 selection 连续性；不要散落在 UI 事件处理器中。
- 新的本地编辑会清空 redo；远端事务通常不会。
- IME composition 应作为一个 history group，而不是每个 composition update 一条记录。

如果最终选用的编辑器内核已经提供可靠的 transaction/history 插件，应复用它，而不是实现平行 history。

## 3. 纯文本转换：纯函数，但明确有损语义

```ts
extractPlainText(document, options): string
parsePlainText(text, policy): DocumentNode
```

两者不是互逆序列化：

- `extractPlainText` 会丢失 mark、链接、批注等结构。
- 应明确段落、列表、硬换行、嵌入节点的转换规则。
- `parsePlainText` 只构造受支持的文档节点，不把文本解释成 HTML。
- 用于持久化和协作的格式应是版本化文档 JSON 或操作协议，不能用纯文本替代。

## 4. DOM 订阅：闭包适配器

DOM 绑定是局部生命周期，闭包比类更直接：

```ts
function bindEditorDom(options: {
  root: HTMLElement
  dispatch: (event: EditorInputEvent) => void
  getSnapshot: () => EditorViewSnapshot
}): () => void
```

它负责：

- `beforeinput`、键盘、paste、selectionchange；
- `compositionstart/update/end`；
- `MutationObserver`——仅在编辑策略确实需要时；
- 将浏览器事件翻译为领域事件；
- 将所有监听器引用捕获在闭包中；
- 返回幂等、只清理本次绑定的 disposer。

不要让 DOM 回调直接修改文档，再由 reducer“同步”。执行路径应是：

```text
DOM event → domain event → transaction/reducer → new snapshot → DOM projection
```

更新 DOM selection 时要比较当前投影或标记更新来源，避免程序化 selection 更新再次触发等价事务。

## 5. 协作连接：类包住资源，内部使用状态机

连接具有稳定身份、socket、重连计时器、pending 队列，因此类是合理选择：

```ts
class CollaborationConnection {
  connect(): void
  send(operation: LocalOperation): void
  subscribe(listener: ConnectionListener): () => void
  close(): void
}
```

类内部不应靠任意布尔组合表达状态，而应调用纯状态机：

```text
idle
  → connecting
  → syncing
  → online
  → reconnecting
  → syncing
  → online

任意非 closed 状态 → closed
```

`closed` 是终态；关闭后旧 socket 的 `open/message/error/finally` 都不能重新发布状态。

连接类拥有：

- socket 或 provider 实例；
- 重连计时器和退避次数；
- 当前连接 generation；
- 未确认操作队列；
- 协议消息解析和外部输入验证。

它不拥有：

- 编辑器 DOM；
- 本地 selection；
- history；
- UI 通知；
- 文档渲染。

## 状态所有权与序列化

| 数据 | 所有者 | 是否序列化 |
| --- | --- | --- |
| 文档工作投影 | editor session/store | 是，使用带 `schemaVersion` 的文档格式 |
| 逻辑 selection | editor view | 可选；恢复或 presence 时使用逻辑位置 |
| DOM `Range`/节点 | DOM adapter | 否 |
| undo/redo | history reducer | 默认不跨会话、不上传 |
| 未确认本地操作 | collaboration workflow | 协议消息需要序列化；内存队列本身不直接序列化 |
| 远端 presence | collaboration presence store | 可传输，但不进入文档 |
| socket、timer、AbortController | connection | 否 |
| connection 状态 | connection state machine | 可记录诊断，不作为恢复资源的快照 |

所有跨网络或存储的数据都使用普通值，并带文档/协议版本。反序列化时在边界验证，内部 reducer 可以依赖已验证契约。

## 竞态策略

不能用一种“取消旧请求”处理所有异步行为。

1. 本地操作必须有序

   每个操作携带 `clientId`、单调 `clientSeq`、`operationId` 和协议要求的 base version。发送队列按序处理；重试依赖服务端去重或所选 CRDT/OT 协议，不能假设超时等于失败。

2. 初始同步与本地编辑并发

   同步期间产生的本地操作进入 pending 队列。权威快照回来后：

   ```text
   authoritative snapshot
       + rebase/replay still-pending local operations
       = visible working projection
   ```

   不能让迟到的快照直接覆盖用户已经输入的内容。

3. 重连响应过期

   每次连接或同步分配 generation。success、error、finally 发布前都检查 generation 和 `disposed`；仅 abort socket 不足以证明旧回调不会执行。

4. IME 与远端更新

   composition 期间不能随意重建正在输入的 DOM。具体采用“重映射 composing range”还是“缓冲远端 DOM 投影到 compositionend”，应由编辑器内核能力决定，但策略必须集中在 DOM/session 边界。

5. acknowledgement 与撤销

   undo/redo 生成正常的协作事务。服务器 ack 只确认对应 `operationId`，不能用旧 ack 中的整个文档覆盖当前投影。

如果服务端没有版本、OT 或 CRDT 等冲突协议，客户端模块不能声称已经实现可靠多人协作；这是必须明确的外部契约。

## 生命周期与销毁

建议 `createEditorSession` 返回一个小型 handle：

```ts
interface EditorSession {
  getSnapshot(): EditorSnapshot
  dispatch(command: EditorCommand): void
  subscribe(listener: EditorListener): () => void
  destroy(): void
}
```

`destroy()` 必须幂等，并按以下原则处理：

1. 先标记 disposed，拒绝新命令和异步发布。
2. 移除 DOM、selection、observer 等视图订阅。
3. 停止重连计时器并取消正在进行的同步。
4. 注销协作消息和 presence 订阅。
5. 关闭该 session 独占的连接。
6. 清空外部监听器和不可再投递的队列。

如果连接由多个编辑器共享，session 只能释放自己的订阅或租约，不能在一个视图卸载时关闭公共连接。每个子资源应清理自己创建的资源，session 只汇总 disposer，不深入操作它们的私有字段。

## 最终判断

不要建立一个同时持有 DOM、文档、history、socket 和所有异步状态的 `EditorManager`。推荐组合是：

- 纯函数承担文档、selection 和纯文本转换；
- Reducer 承担可重放的编辑与 history 转移；
- 状态机规定协作连接的合法生命周期；
- 闭包拥有局部 DOM 订阅；
- 类拥有长期存在的网络资源和不变量；
- session 只负责组装、命令路由与幂等销毁。

这也为一个现实后续变化保留了局部修改路径：将 WebSocket 协议替换为 CRDT provider 时，主要替换 `collaboration` 边界；文档转换、DOM 订阅、selection 和公开 session API 无需随之重写。

## 目标结构

建议只调整商品路由附近的模块，例如：

```text
app/products/[handle]/
  page.tsx                         # Server Component，页面编排与 SEO 内容
  loading.tsx                      # 路由导航骨架
  error.tsx                        # 主商品加载失败与重试
  actions.ts                       # 加购、切换货币等 Server Actions
  _components/
    product-configurator.client.tsx
    currency-picker.client.tsx
    recommendations.tsx            # async Server Component
    recommendations-error.client.tsx
lib/catalog/
  product.server.ts                # 商品查询、缓存、DTO 映射
  recommendations.server.ts
  contracts.ts                     # 可传给浏览器的纯数据类型
lib/shopify/
  client.server.ts                 # 私有 Shopify 客户端
```

这只是商品页的局部边界，不移动布局、购物车或其他页面，也不为采用 Server Components 重构无关代码。

| 单元 | 运行位置 | 职责 |
|---|---|---|
| `page.tsx` | Server | 解析 handle 和用户市场、加载主商品、输出正文和 JSON-LD、处理 404 |
| `generateMetadata` | Server | 标题、描述、canonical、OG；复用同一商品读取函数 |
| 商品正文 | Server | 标题、图片、描述、首屏价格和库存语义 |
| `ProductConfigurator` | Client | 规格/数量状态、派生当前 variant、提交加购 |
| `CurrencyPicker` | Client + Server Action | 提交货币偏好，由服务端写 cookie/session 并重渲染 |
| `Recommendations` | Server | 独立加载、流式输出、局部失败 |
| Shopify gateway | Server only | 凭据、GraphQL、外部响应校验和 DTO 映射 |

`page.tsx` 删除 `"use client"`；Client 边界放在交互叶子上，因为 `"use client"` 会把其导入子图纳入客户端，而跨边界 props 必须可序列化。[Next.js Server/Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components)

## 数据与序列化契约

不要把 Shopify SDK 对象、GraphQL 原始响应、错误对象、凭据或任意附加字段传给客户端。建立显式 DTO：

```ts
type MoneyDTO = {
  amount: string;       // 保留 Shopify 十进制定点字符串
  currencyCode: string;
};

type VariantDTO = {
  id: string;
  selectedOptions: Record<string, string>;
  price: MoneyDTO;
  compareAtPrice: MoneyDTO | null;
  availableForSale: boolean;
};

type ProductConfiguratorDTO = {
  productId: string;
  options: Array<{ name: string; values: string[] }>;
  variants: VariantDTO[];
  initialVariantId: string;
};
```

客户端只保存 `selectedOptions`、`quantity` 和提交状态；当前 variant、价格和是否可购买都由 DTO 派生，避免第二份价格状态。金额使用服务端返回的 `amount + currencyCode`，展示时使用 `Intl.NumberFormat`，不在浏览器自行换汇。

若真实商品存在数千个 variants，应先测量 RSC payload；确有体积问题时再将规格矩阵和按选择查询拆成窄接口，不预先建设通用选品引擎。

Shopify 模块首行加入 `import "server-only"`，并确保凭据没有 `NEXT_PUBLIC_` 前缀。这样客户端误导入会在构建时报错。[Next.js 防止环境污染](https://nextjs.org/docs/app/getting-started/server-and-client-components#preventing-environment-poisoning)

## 货币与价格

服务端解析一个明确的 `PricingContext`，例如：

```ts
type PricingContext = {
  market: string;
  countryCode: string;
  currencyCode: string;
};
```

建议优先级为：

1. 已登录用户的服务端偏好；
2. 服务端写入、白名单校验过的货币 cookie；
3. 商店默认市场。

通过 Shopify Markets/contextual pricing 请求权威价格。浏览器提交的货币、variant ID、数量和价格全部是不可信输入；加购 Action 必须重新确认 variant、有效数量、市场和可售状态，绝不能采用客户端提交的金额。

货币切换由 Server Action 写入 cookie，然后让当前树重新渲染；Next.js 会在 Server Action 修改 cookie 后重渲染当前页面。[Next.js Updating Data](https://nextjs.org/docs/app/getting-started/updating-data#cookies) 不要以 `router.refresh()` 代替服务端缓存失效，因为它只刷新当前路由客户端缓存，不会使服务端数据缓存失效。[useRouter](https://nextjs.org/docs/app/api-reference/functions/use-router)

## SEO 与 Suspense

主商品是首屏、索引和购买的共同依赖，因此在 `page.tsx` 中直接 `await`：

```tsx
const product = await getProduct(handle, pricingContext);

return (
  <>
    <ProductContent product={product} />
    <ProductConfigurator initialData={toConfiguratorDTO(product)} />

    <Suspense fallback={<RecommendationsSkeleton />}>
      <Recommendations
        productId={product.id}
        pricingContext={pricingContext}
      />
    </Suspense>
  </>
);
```

具体原则：

- 主商品不存在时调用 `notFound()`，不是渲染空页面。
- 主商品不放进推荐商品的 Suspense 边界，避免核心内容被次要请求拖住。
- 推荐失败不能使商品正文消失；骨架尺寸应稳定，减少布局跳动。
- 不用 `Promise.all(product, recommendations)`，否则推荐失败会升级为整页失败，也失去独立流式输出。
- `loading.tsx` 负责路由导航等待；推荐列表自己的 Suspense 负责局部等待，两者用途不同。

`generateMetadata` 只存在于 Server Component，并调用与页面相同的商品 accessor，以框架 memoization或请求级 memoization避免重复 Shopify 请求。[generateMetadata](https://nextjs.org/docs/app/api-reference/functions/generate-metadata)

服务端正文输出 Product JSON-LD；内容来自 Shopify，写入 `<script>` 前至少将 `<` 转义为 `\u003c`，避免把 JSON 序列化误当成脚本上下文安全处理。[Next.js JSON-LD 指南](https://nextjs.org/docs/app/guides/json-ld)

canonical 指向稳定商品 URL。规格切换默认不创建新的可索引 URL；无 cookie 的爬虫看到商店默认市场及与页面一致的结构化价格。

## 缓存作用域和失效

| 数据 | 缓存范围与 key | 失效 |
|---|---|---|
| 商品标题、描述、媒体 | 公共；`productId/handle + locale` | Shopify 商品 webhook + TTL 后备 |
| 上下文价格、可售状态 | 仅相同 `product + market/country/currency` 共享 | 价格表、市场、商品或库存事件；短 TTL |
| 通用推荐 | `seedProduct + market + locale` | 商品/推荐源变化 + TTL |
| 个性化推荐 | 用户或请求级，禁止公共共享 | 会话变化；通常 `no-store` |
| 用户货币偏好 | 请求/session | 用户切换时立即生效 |
| 购物车 | 用户/session，通常 `no-store` | 每次购物车 mutation 后读取权威结果 |

关键约束：

- 读取 cookie 后整页属于请求相关输出，不缓存为跨用户共享 HTML；缓存底层可共享商品片段。
- 价格缓存 key 必须包含完整市场上下文。若存在会员价或客户分组价，还必须包含相应授权身份，或者直接不做跨请求缓存。
- 加购不能依赖可能陈旧的商品缓存，Action 应向 Shopify 做权威校验。
- 商品 webhook 使用细粒度 tag，例如 `product:{id}`、`pricing:{id}:{market}`；商品目录允许短暂陈旧时使用 SWR 式 `revalidateTag`。
- 购物车要求 read-your-own-write；若当前版本支持且项目已有缓存，可使用 `updateTag`，否则直接返回 mutation 后的购物车并刷新既有购物车 owner。
- 自托管多实例时，必须确认 tag 失效能在实例间同步。

当前 Next.js 的 Cache Components 模型使用 `use cache`、`cacheTag`、`cacheLife`；`revalidateTag` 是后台 SWR，而 `updateTag` 用于立即过期。[Next.js Revalidating](https://nextjs.org/docs/app/getting-started/revalidating) 但由于仓库没有版本信息，实施时应先检查版本和 `cacheComponents` 配置：旧版本沿用项目已有的 `fetch(..., { next: { revalidate, tags } })` 或缓存封装，不混搭两代模型。

## 错误与恢复

- 商品不存在：`notFound()`，返回真正 404。
- Shopify 主请求暂时失败：交给该商品 route segment 的 `error.tsx`；提供“重试”并保留关联 ID，服务端日志不得包含 token 或完整用户数据。
- 推荐失败：显示“推荐暂时不可用”和局部重试；真实空结果显示空态，两者不能混同。
- 规格不可售：保留选择并禁用加购，用可感知文本说明原因。
- 加购业务拒绝：Server Action 返回带类型的字段错误，保留规格和数量。
- 加购超时、结果未知：不要自动重复 mutation，以免重复加购；先刷新/读取权威购物车再决定是否允许重试。
- 连续点击：客户端 pending 时禁用按钮；这只是体验保障，服务端仍需处理重复或未知结果。
- Shopify 返回的实际币种与请求不一致：展示实际 `currencyCode` 并记录可诊断错误，不能把它静默标成用户选择的币种。

+# Headless Dialog primitive
+
+这个包把三个产品重复实现的模态交互收敛成一个无样式的 React primitive。它只负责打开状态、Portal、语义、焦点、键盘、嵌套层级和清理；标题文案、业务操作、布局、遮罩与内容样式仍由产品组合。
+
+## 公开 API
+
+包只暴露根入口 `@fixture/headless-dialog`，内部 focus/layer 模块不形成兼容承诺。既可使用 `Dialog.Root` 组合，也可单独导入 `DialogRoot` 等具名组件；所有 DOM primitive 都转发 ref 和原生属性。
+
+```tsx
+import { Dialog } from '@fixture/headless-dialog'
+
+<Dialog.Root defaultOpen={false} onOpenChange={(open, details) => {}}>
+  <Dialog.Trigger className="productButton">Edit profile</Dialog.Trigger>
+  <Dialog.Portal>
+    <Dialog.Overlay className="productOverlay">
+      <Dialog.Content className="productDialog">
+        <Dialog.Title>Edit profile</Dialog.Title>
+        <Dialog.Description>Update your public information.</Dialog.Description>
+        {/* 产品表单和业务按钮 */}
+        <Dialog.Close>Cancel</Dialog.Close>
+      </Dialog.Content>
+    </Dialog.Overlay>
+  </Dialog.Portal>
+</Dialog.Root>
+```
+
+- `Dialog.Root`: `open` + `onOpenChange` 为受控模式；省略 `open` 后由 `defaultOpen` 初始化非受控模式。`onOpenChange` 的第二个参数给出 `trigger | close-button | escape-key | pointer-outside` 原因。
+- `Dialog.Trigger`: 原生 `button` 属性；自动连接 `aria-haspopup`、`aria-expanded` 和 content id。
+- `Dialog.Portal`: 默认挂到 `document.body`；`container` 可指定同一 document 内的宿主。Portal 只在 effect 后建立，所以服务端与水合首帧一致。
+- `Dialog.Overlay`: 只有指针直接落在遮罩上才关闭；消费者可在 `onPointerDown` 中 `preventDefault()` 取消。
+- `Dialog.Content`: `role="dialog"`、`aria-modal`、焦点圈定、初始/恢复焦点和最上层 Escape。可用 `initialFocusRef` 指定初始焦点；`onOpenAutoFocus`、`onCloseAutoFocus`、`onEscapeKeyDown` 可通过 `preventDefault()` 覆盖默认动作。
+- `Dialog.Title` / `Dialog.Description`: 自动为 Content 建立 `aria-labelledby` / `aria-describedby`。每个 Content 应提供 Title，或直接给 Content 提供 `aria-label` / `aria-labelledby`；Description 可省略。
+- `Dialog.Close`: 产品自己提供文案与样式的关闭按钮。
+
+当前发布物为 tree-shakeable ESM 和 `.d.ts`，React/React DOM 是 peer dependency。`npm run build:package` 产出 `package-dist`，`npm run check:package` 检查真正进入 tarball 的文件。
+
+## 实现边界
+
+Root 是打开状态的唯一所有者，不接管任何业务状态。Content 注册到每个 `document` 独立的 layer manager；manager 只让顶层 Dialog 响应 Escape 和焦点圈定，并对顶层 Portal 之外的兄弟节点设置可恢复的 `inert`/`aria-hidden`，同时以引用计数语义锁定页面滚动。Content 卸载时恢复本层触发器，嵌套关闭因此回到父 Dialog 内的局部触发器。
+
+Portal 是浏览器能力边界：服务端仍输出稳定的 Trigger，客户端完成 hydration 后才创建宿主并挂载弹窗。primitive 不读取产品主题、不注入 CSS、不包含 Close 等固定文案，也不判断保存/取消等业务含义。
+

+type InertState = {
+  ariaHidden: string | null
+  inert: boolean
+}
+
+type DialogLayer = {
+  content: HTMLElement
+  portal: HTMLElement
+}
+
+export type DialogLayerManager = {
+  isTop: (content: HTMLElement | null) => boolean
+  register: (layer: DialogLayer) => () => void
+}
+
+const layerManagers = new WeakMap<Document, DialogLayerManager>()
+
+function createLayerManager(document: Document): DialogLayerManager {
+  const layers: DialogLayer[] = []
+  const originalInertStates = new Map<HTMLElement, InertState>()
+  let originalBodyOverflow = ''
+  let observer: MutationObserver | null = null
+
+  function restoreElements() {
+    for (const [element, state] of originalInertStates) {
+      element.inert = state.inert
+      if (state.ariaHidden === null) {
+        element.removeAttribute('aria-hidden')
+      } else {
+        element.setAttribute('aria-hidden', state.ariaHidden)
+      }
+    }
+  }
+
+  function hideSiblingsOf(element: HTMLElement) {
+    let current: HTMLElement | null = element
+
+    while (current && current !== document.body) {
+      const parent: HTMLElement | null = current.parentElement
+      if (!parent) break
+
+      for (const sibling of parent.children) {
+        if (!(sibling instanceof HTMLElement) || sibling === current) continue
+
+        if (!originalInertStates.has(sibling)) {
+          originalInertStates.set(sibling, {
+            ariaHidden: sibling.getAttribute('aria-hidden'),
+            inert: sibling.inert,
+          })
+        }
+        sibling.inert = true
+        sibling.setAttribute('aria-hidden', 'true')
+      }
+
+      current = parent
+    }
+  }
+
+  function syncModalIsolation() {
+    restoreElements()
+
+    const topLayer = layers.at(-1)
+    if (topLayer) {
+      hideSiblingsOf(topLayer.portal)
+      document.body.style.overflow = 'hidden'
+      return
+    }
+
+    originalInertStates.clear()
+    document.body.style.overflow = originalBodyOverflow
+  }
+
+  return {
+    isTop(content) {
+      return Boolean(content && layers.at(-1)?.content === content)
+    },
+    register(layer) {
+      if (layers.length === 0) {
+        originalBodyOverflow = document.body.style.overflow
+        observer = new MutationObserver(syncModalIsolation)
+        observer.observe(document.body, { childList: true, subtree: true })
+      }
+
+      layers.push(layer)
+      syncModalIsolation()
+
+      return () => {
+        const index = layers.lastIndexOf(layer)
+        if (index !== -1) layers.splice(index, 1)
+
+        if (layers.length === 0) {
+          observer?.disconnect()
+          observer = null
+        }
+        syncModalIsolation()
+      }
+    },
+  }
+}

+export function getDialogLayerManager(document: Document) {
+  let manager = layerManagers.get(document)
+  if (!manager) {

+  }
