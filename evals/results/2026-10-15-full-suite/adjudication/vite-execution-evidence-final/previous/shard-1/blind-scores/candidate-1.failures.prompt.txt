+# Vite Feature Flags
+
+Expose an explicit, client-safe subset of a JSON feature-flag file through
+`virtual:feature-flags`. The same virtual module implementation is used by the
+Vite development server, SSR module loading, production builds, and watch/HMR.
+
+## Usage
+
+```ts
+// vite.config.ts
+import { featureFlags } from '@frontend-architect-eval/feature-flags'
+import { defineConfig } from 'vite'
+
+export default defineConfig({
+  plugins: [
+    featureFlags({
+      source: new URL('./flags.json', import.meta.url),
+      expose: ['checkoutV2', 'theme'],
+    }),
+  ],
+})
+```
+
+Load the virtual-module declaration once in the consumer's `tsconfig.json`:
+
+```json
+{
+  "compilerOptions": {
+    "types": ["@frontend-architect-eval/feature-flags/virtual"]
+  }
+}
+```
+
+Then import the readonly flags:
+
+```ts
+import { flags } from 'virtual:feature-flags'
+
+flags.checkoutV2
+```
+
+By default, values are typed as `boolean | number | string`. Applications that
+own a narrower schema can add a declaration file and get exact keys and values:
+
+```ts
+import 'virtual:feature-flags'
+
+declare module 'virtual:feature-flags' {
+  interface FeatureFlagSchema {
+    checkoutV2: boolean
+    theme: 'dark' | 'light'
+  }
+}
+```
+
+The main package exports `featureFlags`, `FeatureFlagsOptions`,
+`FeatureFlagValue`, and `FeatureFlags`. The `./virtual` export is the declaration
+entry point; application code imports the Vite-owned `virtual:feature-flags`
+module, not that package subpath at runtime. Internal files are intentionally not
+exported.
+
+## Security and diagnostics
+
+`expose` is a required allowlist. The plugin builds a new object containing only
+those keys before it serializes any data, so other fields never enter generated
+JavaScript or its source maps. Do not expose credentials: flags are public
+client data, not authorization controls or secrets.
+
+The source must be a top-level JSON object whose exposed values are strings,
+finite numbers, or booleans. Invalid options, unreadable or malformed JSON,
+missing flags, and unsupported values fail startup/build with a stable diagnostic
+code, the source path when relevant, and a corrective action.
+
+## Source maps, cache, and HMR
+
+This plugin does not transform consumer source, so it cannot discard or offset
+consumer source maps. It returns a dedicated virtual module containing only the
+allowlisted projection. When Vite emits source maps, any `sourcesContent` for
+that module is therefore client-safe by construction. The package's own build
+also publishes JavaScript and declaration source maps.
+
+Vite's module graph is the sole runtime cache. The plugin reads and validates
+the source whenever Vite loads the virtual module, registers the JSON file as a
+watch dependency, and invalidates that exact module when the file changes. A
+single-file polling bridge covers filesystems where native watch events are not
+reliable; it feeds Vite's normal watcher/module graph and is disposed with the
+plugin. The plugin does not maintain a second flag cache, so dev, build, rebuild,
+and SSR cannot disagree because of stale plugin state.
+
+## Verification and releases
+
+From the repository root, `npm run check` verifies declarations, a real Vite
+production build, source-map secret exclusion, dev/SSR HMR, actionable
+diagnostics, and installation from `npm pack`. `npm test --workspace
+@frontend-architect-eval/feature-flags` adds focused public-API and adversarial
+key checks.
+
+Version changes by consumer impact:
+
+- Patch: diagnostics wording improvements that preserve codes, fixes, and wider
+  compatible Vite ranges after matrix verification.
+- Minor: optional configuration or new exports that preserve generated module
+  semantics.
+- Major: changing accepted flag values, virtual exports, diagnostic codes,
+  runtime mutability, package entry points, or the supported Vite/Node floor.
+
+Deprecations should name the replacement in release notes and remain available
+for at least one minor line before a major removal. High-risk lifecycle changes
+should ship as a prerelease and be exercised against representative consumer
+projects before promotion.
