# 完整 45 案例对照方法

日期：2026-10-15。比较上一轮精简前工作区快照与精简后快照，两个条件均加载对应
版本的 Skill，主对照目标为每条件 45 个完成样本；未完成尝试与复测另行保留。
previous 不是无技能 baseline；
本轮针对精简退化，不用于证明安装技能相对无技能的收益。

## 固定输入与配置

- 45 个用例、rubric、6 个实现夹具及供 2 个评审案例复用的一组 before/after 快照，
  均从同一当前工作区冻结。
  其余 37 个用例为内联原始材料，主要评价方案和判断。
- 两个 Skill 条件取自上一轮保存的精确快照，包含精简前已有的未提交变更。
- 模型配置为 gpt-5.6-sol、high；CLI 为桌面应用自带的 0.162.0-alpha.17.2。
  型号别名固定，但服务端没有暴露精确模型构建版本。
- 每个案例独立临时 Git 工作区，禁用插件、Apps、多代理及用户配置；通过单次 CLI
  配置禁用已发现的 222 个全局技能路径，并将 project_doc_max_bytes 设为 0。
  不修改用户全局设置。配置字段依据[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。
- 生成会话使用 workspace-write，评分使用 read-only；父流程在宿主执行冻结的验收命令。
  因而生成者可能遇到浏览器或网络限制，而父流程可以运行真实 Chromium。共享宿主及
  依赖缓存没有制作系统镜像，不能把这些环境因素归因为指导变化。
- 三个独立分组并行，同一案例依次生成 previous 与 candidate。生成者看不到 rubric、
  must_observe、fail_if、另一条件结果或父代理结论。
- Skill 指导副本包含入口、references 和其所属 CONTRIBUTING.md，均作为只读输入；
  维护讨论只能描述拟议修改，不能改写实验指令。

冻结文件及摘要在 frozen-inputs/ 与 input-hashes.json；保存的入口命名为
SKILL.snapshot.md，避免成为可发现技能。实际运行时恢复为临时源目录中的 SKILL.md。
run-plan.json 保存型号、CLI 路径、分组及隔离参数；execution/ 保存实际调度方法。

## 采集与评分

复用仓库 run_behavior_evals.py 与 score_behavior_evals.py。保留每例的用户请求、
原始 JSONL、stderr、回答、相对固定初始提交的 diff、验证日志和冻结契约。执行证据
缺失、读取不可判断、越界读取或改弱验收不计为通过。
分组用 `--append` 逐例采集，命令退出码会汇总该分组此前全部记录；早先的未知审计或
测试失败也会使后续采集命令返回 1。单例结果以 manifest 中的 generation、validations、
最终原始事件审计与独立评分判断，不能把该汇总退出码当作每个新案例都生成失败。

评分使用同一固定模型配置，在新的独立会话中分两阶段完成：第一阶段只接收匿名单一
条件、原始输入、回答、diff、验证与 rubric；第二阶段再单独审计该例 fail_if 和必要的
reference 路由理由。两阶段均不接收另一条件输出或 must_observe。任一失败项覆盖分数。
这能避免作者自评和跨条件补分，仍不能消除同系列模型之间的相关性。

逐例比较新增失败、代码验收和分数变化；单次分数下降只作为复查信号。初次采集和复测
分开保留，不把修复或重试后的结果写成首轮一次通过。无效样本不进入质量均分。

在任何正式评分落盘之前确定复查范围：所有降分逐项阅读原始证据；新增失败、verdict
下降或归一化降幅至少 1 分的案例，按相同配置新建双条件复测。其他降分若对应实际新增
遗漏，也进入复测；不能仅凭一次降分宣称稳定退化或仅凭均分掩盖单项失败。
另外全部 6 个可执行案例各补一组新旧复测，保留首轮结果。首轮旧版乐观更新生成时曾因
沙箱网络限制无法安装依赖；父流程随后安装成功，新版可能受益于缓存。每例在主对照
两条件均采集完成后才开始复测，不清空共享依赖缓存、不修改夹具，以复查此环境
因素与实现结果波动。可执行复测最多四个会话并行；每次采集写独立目录，再原样聚合
到评分目录，聚合副本不另计样本。
旧版 Vite 插件及 Dialog 首次生成触及 900 秒上限，原始记录完整归档到 attempts/，
不进入质量均分。这两例新旧主对照都改为 1800 秒上限后采集；全部可执行复测也统一
使用 1800 秒上限。
时限不进入模型提示词；型号、推理强度、任务、指导与验收契约均不改变。不比较这两批耗时。

   成功生成与评分的 gpt-5.6-sol 和桌面应用自带 CLI；不同配置预检不进入正式比较。
2. 原隔离副本缺少入口引用的 CONTRIBUTING.md，补齐维护来源，并增加真实工作区
   回归，保证无技能条件不包含指导文件。完整脚本测试最终为 67 项通过。
3. 首批采集将纯 find 枚举误判为读取未知；一个维护案例还改写了指导副本。首批已停止
   并完整保留于 ../2026-10-15-full-suite-initial-capture/，未混入本批。补上指导只读
   输入约束后重新冻结了本批全部模型输入。
4. 本批又观察到 pwd、rg --files、git status 的纯元数据组合及只输出文件名的
   git diff --name-only 被误判。只修正读取审计，
   不改变用户请求或模型指导。评分前用审计 v5 对未改变的 JSONL 重算，另存原审计；
   仍拒绝夹带读取、执行、写文件或删除动作的命令。修复前后证据见
   audit-repair-evidence.json，原 v3/v4 实现保存在 execution/。capture-protocol-check.json
   确认提示词、工作区初始化、任务契约与验收函数没有改变。
5. 超时日志还暴露了目录枚举及显式排除指导目录的项目搜索被误报。补充这些窄形式的
   识别，加入管道、重定向、命令替换、额外目标和非工作区目录的反例测试。此修复不
   改变 v5 审计结构；audit-search-compatibility.json 确认此前 74 个完成样本的审计结果
   逐字不变，因此已开始的评分输入和缓存没有变化。原解释器也保存在 execution/。
6. Vite 重采集还执行了成功但空输出的 `git diff -- <字面路径>`，用于检查指导及保护文件
   是否变化。修正其读取误报；这类命令不建立已读或不可变证明，正式核验仍比较指导副本
   与冻结文件。没有放宽非空 diff、重定向或未完成生成的检查。
7. 旧版 Vite 复测的纯元数据组合含 `git log --oneline -5`，触发读取误报。补充此窄形式，
   保留原无效评分再重新独立评分。audit-log-compatibility.json 确认 90 个主样本和首批
   6 个复测样本的审计结果不变；只恢复这一个被误报样本，不改原始事件与行为检查。
8. 上述重评分首次命令遗漏临时 CLI PATH，已停止准确进程树，相关输出完整移到
   blind-scores.wrong-cli-attempt，未复用缓存；使用原冻结 wrapper 从空评分目录重跑。

## Vite 的补充证据复核

主评分将旧版“插件单测通过”判为未运行，但原始事件实际有两次单测成功，最终一轮
为 2/2。标准评分视图只给出了父流程验收日志，没有这段生成阶段执行输出。为区分
证据遗漏与实际虚假声明，两条件分别在新的匿名会话中补充同类原始包命令、退出码、
输出与文件变动顺序，rubric、失败项和生成产物均保持不变，不提供原分数或复核预期。

初次补充视图把开发中已修复的红灯也解释为最终失败，质量评分口径出现不一致；该轮
保存在 adjudication/vite-execution-evidence。最终复核明确区分生成阶段开发过程和
最终 VALIDATIONS，再按相同规则盲评两条件，保存在其 -final 目录。主对照原分数没有
被覆盖，补充复核不另计生成样本，也不混入主对照均分。实际脚本保存在 execution/。

## 证据能力边界

阅读审计只覆盖可见执行事件，不能证明任意程序内部没有隐式文件访问；摘要核对也不是
防篡改签名。父代理最终核验实际产物与失败项，不能用最终回复的自述替代原始执行证据。

## 复现

为每个条件复制 frozen-inputs 中的对应目录到新的临时源目录，将 SKILL.snapshot.md
恢复为 SKILL.md。将 execution/codex 所在目录放到本次命令 PATH 前部，确认它引用的
同版本 CLI 存在；用独立 Python 环境安装仓库 requirements-dev.txt。分别对两个临时
源目录运行其 scripts/run_behavior_evals.py，指定 --mode candidate、--model gpt-5.6-sol、
--reasoning-effort high 和全新的结果目录，再按相同配置运行 score_behavior_evals.py。
必要的元数据重审包装保存在 execution/re_audit_and_score.py；不得用它豁免真实未知
阅读或缺失日志。不要直接重跑调度脚本覆盖本次记录。

最终结果及尚未验证范围由 report.md 记录；summary.json 与 comparison.csv 仅汇总
已实际落盘的采集和评分，运行中缺项保持缺项，不能据空失败列表宣称没有退化。
