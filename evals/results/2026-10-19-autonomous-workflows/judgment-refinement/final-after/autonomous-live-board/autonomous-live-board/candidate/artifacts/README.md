# Team board

实现设计与验证依据见 [卡片排序设计](docs/card-reordering-design.md)。

实现当前项目的卡片排序。`src/data.mjs` 提供 80 张稳定 ID、不同内容长度的卡片，
`src/api.mjs` 已提供保存顺序的调用。页面使用原生 ESM，不更换技术栈。

用户可用每张卡片的 Move up / Move down 按钮，也可从 Move card N 手柄拖到另一张
卡片上。成功操作立刻更新业务顺序，卡片在新旧位置之间平滑移动；移动中仍可继续操作，
位置不能突然跳回旧位置。按钮操作后焦点跟随同一卡片。只有一个顺序事实；保存中可
继续改，最终持久化最近的顺序，旧响应不得覆盖后来操作，失败须有可见反馈和 Retry save。

保留 Show board / Hide board 切换。滚动、调整窗口、隐藏及重新显示不能留下悬空动画、
幽灵卡片或异步回调重新打开看板。遵守减少动态效果的系统偏好，此时直接给出静态终态。
Board 列表及卡片 ID 是当前视图的公开标记；每张卡片保留 `data-card-id`。

`npm run check` 在真实 Chromium 中检查产品操作，并记录固定数据、视口和操作序列下
的浏览器成本原始数据。保存服务由测试中的 HTTP 替身提供，不能把此结果称为线上服务验收。
