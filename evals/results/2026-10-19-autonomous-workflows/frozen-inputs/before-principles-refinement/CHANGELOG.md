# Changelog

本文件记录 Frontend Architect Skill 的可安装发布版本。Git tag 是发布内容的不可变标识，
`VERSION` 是仓库中的当前版本单一来源。

## [Unreleased]

- 将需求开发与架构设计贯通：从简短目标自主发现上下文，结合功能拆分设计职责、接口与数据流，并用实现和验证反馈修正设计；仅设计或仅审查按请求限定交付边界，开发交付前用同一工程标准检查实际代码。
- 普通审查默认同时核对当前有效需求和工程质量，涵盖现有代码及调用关系；不以全绿测试代替可维护性判断，不依赖用户额外列出审查维度。简化技能调用示例和默认提示。
- 增加四项短请求用例，定向复测开发、架构和两类审查，并保留局部修改对照；补清图示有效性、设计落盘和审查责任边界。复测与实际产物检查通过，91 项脚本回归通过；未运行完整 60 例，失败、评分漏判和证据限制见[自主流程验证](evals/results/2026-10-19-autonomous-workflows/report.md)。
- 需要设计的功能开发、职责重构、共享基建与迁移默认先写技术文档，明确实施步骤、每步功能和函数或类契约，并包含技术架构图与数据流转图；局部既定修改保持轻量路径，文档不增加审批门槛。
- 增加仅提供需求与技能的条件字段和导出职责重构用例，核对文档先行、设计完整性与实际功能，保留局部修改和文档深度对照。
- 定向对照保留原版和无技能组缺少先行设计、首轮图示语法错误及评分漏判；细化规则后重新生成，两项功能检查及四张图的解析通过。过程和限制见[需求开发流程验证](evals/results/2026-10-19-design-workflow/report.md)。

## [0.5.0] - 2026-10-16

### Changed

- 将入口从 327 行收敛到 153 行，按需披露专题与章节；统一实现和 review 的函数职责、调用契约、状态与副作用所有权标准，保留必要抽象、主动前瞻和授权范围内的自主性。
- 领域含义与长期决策复用项目已有文档；按实现、检查接线、环境、信息发现和判断指导定位维护责任，减少重复规则。
- 补强根因辨别、异步编辑身份、完整交互的稳定结果与恢复验收；交付开头、总结及后续修复轮的就绪声明与决定性证据保持一致。
- 长期验证结论保存可复核输入、原始产物与证据边界，复用已有记录及存储，不要求每次局部修改建档。

### Evaluation tooling

- 行为案例由 38 项扩展到 54 项，补充真实交互、多文件 review、函数与调用边界、领域契约和局部修改的正反场景及可执行检查。
- 读取审计区分标题发现与正文，按相关性判定路由；保留隔离检查，取消与正文契约矛盾的主题配额和逐项旁白要求。
- 实现型采集允许最多一次有界宿主反馈，逐轮保留失败、修复和复验并校验哈希；修正成功打包缓存重跑的评分证据遗漏。

### Verification and limits

- 发布前仓库校验、主技能和维护子技能的官方校验及 91 项确定性回归通过，版本、变更记录和安装引用一致；详情见[发布验收](evals/results/2026-10-16-release-0.5.0/report.md)。
- 保存[完整 54 例历史对照](evals/results/2026-10-16-full-suite-54/report.md)及其失败、评分分歧和环境诊断；后续[定向优化](evals/results/2026-10-16-confirmed-issues-optimization/report.md)共 26 份采集、30 次生成，主结果为 23 target、1 fail、2 invalid。最终 153 行版四类前向验证均为 target，原失败和无效采集未改写。
- 最终版未重跑完整 54 例；Dialog 新旧首轮无有效配对。其他模型、自动技能选择、真机、辅助技术及完整浏览器/React 兼容矩阵未验证，不据此宣称稳定无退化或普遍保证代码质量。

## [0.4.2] - 2026-09-15

- 测试布局遵循用户和项目约定，支持集中组织，迁移时核对发现范围及实际执行用例。
- 增加命名与集中测试迁移行为案例；新增案例尚未进行独立行为评测。

### Verification

- 本次按维护者请求发布规则修订，新增案例尚未独立评测，不宣称行为效果已经提升。

## [0.3.0] - 2026-09-09

### Added

- 增加异步请求与资源生命周期专题，覆盖竞态、重试、回滚、清理和受控 Promise 验证。
- 增加字段资格与搜索生命周期两个可执行评测，以及独立的第二阶段需求变更验证。
- 保存新旧技能的代码生成结果、验证日志和匿名独立评审，明确证据边界。

### Changed

- 围绕行为、事实、模型、边界、实现和证据组织开发流程，按风险选择文档深度。
- 强化领域语义、状态所有权、完整控制流、异常边界、变更局部性和真实用户结果验证。
- 将机械的 reference 数量限制改为按需加载与可审计的扩展理由，保留评测隔离检查。

### Verification

- 26 个确定性脚本测试通过；25 个行为评测用例通过结构校验。
- 两个代码任务的新旧技能结果均通过第一阶段及后续变更测试，匿名评审未发现重要缺陷。
- 本轮每条件仅一次实验，不包含无技能基线；尚不能证明新版稳定优于旧版或覆盖大型前端项目。

## [0.2.0] - 2026-08-24

### Added

- 增加信息隐藏与深模块判断，避免把改名转发的浅层封装误判为架构边界。
- 增加候选 Skill、reference 和无 Skill baseline 的隔离审计。
- 增加受保护评测 harness，阻止候选通过修改既有验收脚本降低通过条件。
- 增加乐观更新并发回滚、source map 秘密扫描和真实 npm tarball 消费验证。

### Changed

- 将单次任务的 reference 路由限制为最多两个主题；渲染专题只允许公共模型加一个目标平台扩展。
- 强化版本、安装、升级和发布校验，确保 README、CHANGELOG、VERSION 与 Git tag 保持一致。
- 修正 GitHub Actions 的 Python 依赖缓存配置。

### Verification

- 19 个确定性脚本测试通过。
- 18 个 Markdown 文件和 18 个行为评测用例通过仓库校验。
- 三个目标行为的跨模型评测平均分由 baseline 11.25 提升至 candidate 15.29，候选均达到 target。
