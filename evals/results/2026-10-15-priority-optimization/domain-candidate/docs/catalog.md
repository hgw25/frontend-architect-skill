# 目录说明

领域定义见 [catalog-language.md](catalog-language.md)，重要选择见 [decisions/012-directory.md](decisions/012-directory.md)。目录行提供卖家资料详情和收藏；收藏保留为本地操作。

## 前端映射

复用 `api/catalog.ts` 的 `SupplierDto`，接口名称和字段不变。当前仅需展示和导航，可以直接使用已有 DTO 或已有行映射，无需新增一套平行实体、状态或身份映射服务。

| 来源 | 前端含义与用途 | 不应采用的替代 |
| --- | --- | --- |
| `SupplierDto.displayName` | 卖家资料名称，沿用目录现有显示与转义方式 | 不解释为登录用户名 |
| `SupplierDto.supplierId` | 行的卖家资料身份、详情路由参数及详情请求标识 | 不替换为 `organizationId`、`userId` 或模糊的 `accountId` |
| `SupplierDto.organizationId` | 计费组织关联；保留原字段 | 不用于打开卖家资料详情 |
| 当前登录会话的 `userId` | 当前操作人；沿用已有会话来源 | 不从目录 DTO 生成作者用户映射 |

如已有行映射层，保留明确的 `supplierId` 和 `organizationId` 字段；不要为文案调整复制一份可独立修改的身份状态。

## 导航方案

1. 将目录相关“账户”文案改为“卖家资料”，同步详情入口及无障碍名称。
2. 在现有详情链接生成处，读取当前行的 `supplierId`，按项目现有路由构造方式放入名为 `supplierId` 的参数。保留已有导航、返回、焦点和链接交互机制，不额外选择路由框架或另建通用导航层。
3. 详情页从该参数取得资料标识，按现有数据访问方式传给原详情接口。链接生成、参数读取及数据请求都使用相同 `supplierId`；与 `organizationId` 无关。
4. 路由缺参、详情不存在或请求失败时，沿用项目现有校验与错误处理，不回退到组织 ID 或登录用户 ID。接口的具体函数名、路径、签名和项目路由形状未在输入材料中提供，接入时在原调用点核对，不能凭此说明新造接口或改外部字段契约。
5. 不增加作者用户链接。收藏按钮继续执行现有本地收藏操作，不能触发详情导航；本次不改变其存储键和持久化语义。

只持有旧 `organizationId` 的资料链接不能据此得到 `supplierId`。不猜测二者相等，也不依靠曾经的一一对应关系自动跳转；旧链接兼容事项见 [导航决定](decisions/012-directory.md)。

## 接入真实项目时的验证

- 用 `supplierId = "supplier-A"`、`organizationId = "org-B"` 的一行点击详情；断言路由携带 `supplier-A`，原详情接口也收到 `supplier-A`。这能发现只改文案、误传组织 ID 和只改参数名的问题。
- 用两个不同 `supplierId`、相同 `organizationId` 的目录行分别打开详情；两次必须指向各自资料。不得因组织相同而合并行身份或共用详情目标。
- 直接进入含 `supplierId` 的详情链接，再刷新和返回目录，按项目既有机制保持正确目标和导航行为；缺参、不存在及请求失败保持既有错误反馈。
- 检查标题、详情文案和无障碍名称采用“卖家资料”，没有新增作者用户入口，也没有新增用户映射请求。
- 点击收藏仍只执行已有本地操作；收藏点击不会触发详情链接，原持久化行为不变。
- 按项目现有命令运行受影响的类型检查及行为测试；不因本次文案和标识调整引入新的技术栈、依赖或测试框架。

本交付只有输入材料和方案文档，没有真实页面、路由、请求实现或运行环境。因此上述是接入验收要求，尚不是已执行的运行时验证结果。
