# 目录说明

领域说明见 [catalog-language.md](catalog-language.md)，身份与导航选择见 [decisions/012-directory.md](decisions/012-directory.md)。当前目录展示“卖家资料”，详情使用 `supplierId`。

## 前端映射

沿用 `api/catalog.ts` 的 `SupplierDto` 和现有接口名称。目录功能的数据映射位置负责以下规则，不在页面、导航和请求层分别猜测身份：

| 输入 | 前端用途 |
| --- | --- |
| `supplierId` | 卖家资料标识；传给详情导航和详情查询 |
| `displayName` | 卖家资料名称；用于现有目录行显示 |
| `organizationId` | 计费组织标识；保持原字段含义，不填入详情导航的 `supplierId` |
| 当前登录会话的 `userId` | 当前操作人；不从 `SupplierDto` 推导 |

优先修改现有目录行映射。若现有行模型需要独立于 DTO，使用明确的 `supplierId` 和 `displayName` 字段即可；无需为这次命名调整增加 DTO/entity/view-model 多层复制、身份注册表或通用适配框架。不要将现有 `accountId` 一类模糊字段继续用于不同身份。

## 详情导航

1. 行上的原“账户详情”入口改为“卖家资料详情”，沿用现有链接交互和路由设施。
2. 导航参数显式为 `{ supplierId: row.supplierId }`。目的地仍为现有资料详情页；路由名称或路径采用项目已有约定。
3. 详情页从路由读取 `supplierId`，传给现有详情请求方式。接口函数名称保持不变；调用参数、类型和对应请求字段须与 `supplierId` 契约一致。不能传 `organizationId`，不能缺少值时回退到其他身份。
4. 保留现有加载、失败、不可用详情反馈，以及返回目录的方式。路由参数解析和编码复用现有路由能力。

导航只需要卖家资料 ID，不传整个 DTO，也不附加计费组织或登录用户 ID。服务端没有用户身份映射，本次没有作者用户链接或用户身份补查。

## 收藏

每行继续保留收藏入口，并沿用现有本地操作和持久化流程。改详情入口时不能让收藏按钮触发详情导航；保持原有事件和键盘交互。收藏身份和旧数据格式需要从实际实现核实，迁移限制见 [目录决策](decisions/012-directory.md)。

## 后续维护与验证

- 检查目录行映射、行详情链接、详情路由参数及详情请求调用点，替换旧的组织身份详情依赖。仅修改目录领域里的旧“账户”名称，不全局替换计费等其他语境的名称。
- 使用 `{ supplierId: "supplier-7", organizationId: "org-42", displayName: "示例卖家" }`：目录显示“示例卖家”，详情导航传 `supplier-7`，详情请求也使用 `supplier-7`，不能使用 `org-42`。分别检查点击入口和直接访问该详情路由。
- 核对现有收藏仍能独立切换、按现有方式保持本地状态，不触发详情导航或新增网络请求；确认没有作者用户入口或用户映射请求。
- 有历史链接时，按决策记录中的兼容约束验证；核实结果和实际迁移办法补充到原决策文件中。
- 后续计费组织新增展示或独立入口，应使用 `organizationId` 的专用契约，不改变资料详情的 `supplierId` 契约。若将来提供用户映射，先明确服务端返回的映射和权限契约，再决定用户入口。

当前提供的材料只包含 DTO 和文档片段，没有可运行应用、路由实现、详情请求函数或收藏存储。以上是实施方案与验收条件；应用行为和兼容迁移尚需在真实代码中验证。
