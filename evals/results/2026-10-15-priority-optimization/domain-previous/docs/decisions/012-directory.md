# 012：目录身份与详情导航

## 当前决策：已接受

目录页面的“账户”已批准改为“卖家资料”。卖家资料、计费组织和登录用户是三种身份；卖家资料详情导航及详情查询使用 `supplierId`。接口名称与 `SupplierDto` 字段保持不变。

目录行映射由目录功能的数据边界负责，导航调用显式传递 `supplierId`，详情页面以该导航标识查询卖家资料。`organizationId` 仅保留计费组织含义，不得作为备用详情 ID。登录用户继续来自登录会话。

服务端没有用户身份映射，本次不增加作者用户入口。收藏继续使用已有本地操作和持久化流程，不新增收藏接口、远端同步或用户身份查询。

## 被取代的历史决策

此前已接受“详情导航使用 `organizationId`”，依据是当时卖家资料与计费组织一一对应。该决定已被上述当前决策取代。保留本节用于解释旧代码和旧链接，不代表继续支持身份互换。

## 实施与兼容约束

- 复用现有路由和数据访问方式；调整卖家资料详情参数的语义和调用点为 `supplierId`，不引入新技术栈或第二套路由层。
- 未提供现有 URL 和路由代码，本文不规定新路径格式。检查现有详情路由后，在该路由内落实明确的 `supplierId` 参数契约。
- 若存在以 `organizationId` 定位详情的历史链接，不能仅改参数名就把它解释为 `supplierId`。先核实现有兼容机制及权威映射；没有可靠映射时，不猜测重定向，使用现有不可用详情反馈并引导从目录重新进入。旧链接兼容规则须在实施时补充到本决策。
- 收藏的现有键及数据格式尚未提供。保留现有本地收藏行为；若检查发现其身份依赖旧的一一对应假设，先明确收藏对象和可验证的迁移规则，再修改存储键。不能直接将旧 `organizationId` 值改称 `supplierId`。

## 验收依据

使用 `supplierId` 与 `organizationId` 不同的目录数据，确认行详情入口、导航参数和详情查询均使用同一个 `supplierId`。同时确认显示名称为“卖家资料”、接口名称不变、收藏仍走本地流程、没有新增作者用户入口或用户映射请求。

领域定义见 [目录领域](../catalog-language.md)，具体前端映射与检查步骤见 [目录说明](../catalog.md)。
