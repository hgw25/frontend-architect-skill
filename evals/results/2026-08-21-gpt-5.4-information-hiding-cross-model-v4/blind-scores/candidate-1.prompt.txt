+# `@frontend-architect-eval/feature-flags`
+
+Vite plugin that exposes a client-safe subset of JSON feature flags through
+`virtual:feature-flags`.
+
+## Public contract
+
+- `featureFlags(options)` reads a JSON file, validates the public keys listed in
+  `options.expose`, and exposes them to both dev and build through the same
+  virtual module.
+- `FeatureFlagPrimitive`, `FeatureFlagsShape`, and `FeatureFlagsOptions` are the
+  supported public types from the package root.
+- `virtual:feature-flags` exports a readonly `flags` object.
+
+## Generated consumer types
+
+The plugin writes `src/feature-flags.generated.d.ts` by default. Consumers keep
+that file in `tsconfig` includes so `virtual:feature-flags` stays typed in the
+editor and in CI.
+
+## Package exports
+
+- `.` exposes the runtime plugin and root types.
+- `./virtual` exposes the ambient declaration for `virtual:feature-flags`.
+
+Internal helpers stay private to preserve room for implementation changes.
+
+## Source maps and secrets
+
+The client module is generated from the filtered public subset only. Unexposed
+values never enter the virtual module code path, so they do not leak into
+bundles or source maps through `sourcesContent`.
+
+## Cache and invalidation
+
+The plugin caches parsed output by source content and `expose` list. When the
+source file changes, it clears the cache, regenerates the declaration, and
+invalidates the virtual module so HMR and SSR reload see the same flags.
+
+## Verification
+
+- package build output and packed files
+- example app type-checking
+- production build artifact inspection
+- dev server SSR/HMR reloading
+- configuration diagnostics
+
+## Versioning
+
+- additive flags or new optional plugin options: minor
+- stronger validation, changed generated types, renamed exports, or changed
+  virtual module behavior: major
+- implementation-only fixes that preserve the public contract: patch
