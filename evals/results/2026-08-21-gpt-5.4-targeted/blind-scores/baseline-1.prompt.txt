+# 卡片列表重排动画方案
+
+## 现状判断
+
+仓库当前只有 `.git`，没有可复用的前端实现、动画库或拖拽代码。因此这里不给出臆测性的“按现有栈接入”，而是先做层级决策，再定义实现边界。
+
+## 方案结论
+
+推荐层级：**FLIP 为核心，配合原生 CSS `transform`/`transition` 实现**。
+
+不建议作为主方案的层级：
+
+- **无动画**：重排反馈太硬，拖拽过程中列表位置跳变，用户很难确认插入结果。
+- **纯 CSS transition**：只依赖 DOM 顺序变化和自动布局，无法稳定处理快速连续拖拽，也很难在滚动容器里保证每次位移都平滑。
+- **View Transitions API**：更适合页面切换或低频状态切换，不适合作为高频拖拽重排主路径。连续拖拽会频繁触发快照，滚动容器和浏览器支持面也会增加约束。
+- **动画库**：如果仓库已经在用动画库可以复用；但当前仓库为空，只为列表重排引入一层库，收益不够高，且会扩大维护面。
+
+选择 FLIP 的原因：
+
+- 能直接针对“前后布局矩形差”做补间，适合列表项重排。
+- 主动画只走 `transform`，性能和可控性都更好。
+- 容易在每次 reorder 时取消上一段动画，适配快速连续拖拽。
+- 对滚动容器兼容性更直接，只要测量在同一坐标系内即可。
+- `prefers-reduced-motion` 可以在这一层统一降级。
+
+## 实现边界
+
+### 1. 动画对象
+
+- **被拖拽卡片**：由拖拽层自己控制位置，通常跟随指针或占位逻辑，不走重排补间。
+- **其余卡片**：在索引变化后执行 FLIP 重排动画。
+- **容器本身**：不做整体位移动画，避免和滚动行为打架。
+
+### 2. 动画时机
+
+在每次列表顺序变更时执行一轮：
+
+1. 记录当前每个卡片的 `First` 矩形。
+2. 应用新的排序结果。
+3. 在下一帧读取 `Last` 矩形。
+4. 计算位移差值，先反向设置 `transform`，再过渡回 `transform: none`。
+
+要求：
+
+- 所有测量与写入收敛到 `requestAnimationFrame`。
+- 新一轮 reorder 到来时，立即取消上一轮未完成动画，再按最新位置重新计算。
+- 不累积 transform，不依赖“上次动画结束”作为下一次起点。
+
+### 3. 滚动容器
+
+- 用 `getBoundingClientRect()` 统一在视口坐标系测量，避免自己手算 `scrollTop` 差。
+- 如果拖拽会触发自动滚动，滚动后的新一轮测量必须按最新视口位置重新取值。
+- 只对当前已挂载的可见卡片做 FLIP。若后续接入虚拟列表，需要把“未挂载项不参与动画”作为明确限制。
+
+### 4. 连续快速拖拽
+
+- 把 reorder 动画视为“可中断的过渡”，不是事务型时间线。
+- 每次索引变化都以最新 DOM 布局为准重新测量。
+- 动画时长保持短且稳定，建议 `120ms` 到 `180ms`，缓动用 `cubic-bezier(0.2, 0, 0, 1)` 或同类收敛型曲线。
+- 不做弹簧类长尾动画，否则在高频拖拽下会出现追帧和拖影。
+
+### 5. Reduced Motion
+
+- 命中 `prefers-reduced-motion: reduce` 时，关闭 sibling tween，直接跳到最终位置。
+- 如果产品希望保留极轻反馈，可退化为 `0ms` 到 `50ms` 的线性过渡，但默认建议直接禁用重排补间。
+- 该降级应只影响重排动画，不影响拖拽功能本身。
+
+## 不纳入本次范围
+
+- 跨列表拖拽的入场/出场动画。
+- 删除、插入、新建卡片的独立动效。
+- 虚拟滚动场景下的完整过渡连续性。
+- 为单一列表重排单独引入第三方动画库。
+
+## 最小实现建议
+
+可以抽成一个轻量能力，而不是一套动画系统：
+
+- `measure()`：收集 `id -> DOMRect`
+- `playFlip(prevRects, nextRects, options)`：执行一轮 FLIP
+- `cancelFlip(id?)`：中断当前项或当前批次动画
+- `motionEnabled`：统一读取 `prefers-reduced-motion`
+
+关键约束：
+
+- 卡片必须有稳定 `id`
+- 动画只修改 `transform`
+- 正在拖拽的卡片排除在 FLIP 集合外
+
+## 验证方案
+
+### 手工验证
+
+1. **单步拖拽**
+   - 慢速拖动一张卡片穿过 1 到 2 个相邻项。
+   - 预期：邻近卡片顺滑让位，被拖拽卡片不出现二次补间。
+
+2. **快速连续拖拽**
+   - 连续快速上下划过多项，频繁改变插入位置。
+   - 预期：列表项始终跟随最新排序，不出现回弹、错位、残留 transform。
+
+3. **滚动容器**
+   - 在可滚动列表中拖到边缘触发滚动，再继续重排。
+   - 预期：滚动后动画方向和距离仍正确，不因 `scrollTop` 变化跳闪。
+
+4. **reduced motion**
+   - 打开系统“减少动态效果”后重复上述操作。
+   - 预期：重排直接落位或极短过渡，不影响功能正确性。
+
+5. **不同卡片高度**
+   - 混合高低不同的卡片进行重排。
+   - 预期：位移按真实高度计算，不出现覆盖或穿插。
+
+### 工程验证
+
+- 在开发态打印单轮 FLIP 的测量数量和取消次数，确认高频拖拽下没有失控增长。
+- 用浏览器 Performance 面板抽查：
+  - 动画期间主线程没有持续长任务。
+  - 主要开销集中在少量测量与合成层变换。
+  - 没有因动画反复触发布局抖动。
+
+### 回归标准
+
+- 快速连续拖拽时，最终视觉顺序始终与数据顺序一致。
+- 任一拖拽结束后，所有卡片内联 `transform` 都能清理回 `none`。
+- reduced motion 下，功能路径与普通模式一致，只移除动效。
+
+## 决策摘要
+
+当前上下文下，**最合适的层级不是 View Transitions API，也不是额外动画库，而是可中断的 FLIP 重排动画**。它最能满足“快速连续拖拽、滚动容器、`prefers-reduced-motion`”这三个核心约束，同时保持实现面和依赖面都可控。
