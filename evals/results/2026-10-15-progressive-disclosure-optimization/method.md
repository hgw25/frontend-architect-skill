# Progressive disclosure comparison

Compare the installed/source-matched local guide 9808c908a471 with a compressed
entry and section routing. Freeze both guidance conditions before generation.
Both explicitly load their guide, use the same six existing tasks, protected
fixtures, current capture/scoring tools, unchanged rubric and CLI isolation.
This is not a no-skill baseline or a full 53-case rerun.

Use gpt-5.6-sol/high with the bundled CLI and 900 seconds per generation.
Three shards each generate previous then candidate for two tasks. Fresh quality
and failure-only graders see one anonymous condition. Generators do not see
the rubric, expected observations, previous outputs or the comparison results.
The same heading-read protocol is available to both conditions; no preferred
reading outcome is injected into a task prompt.

Selected tasks cover an explicit local edit needing no domain documents,
function/caller quality, review of green but coupled code, root cause versus
recovery, a real browser interaction journey, and a shared Dialog contract with
legitimate cross-topic needs. Inspect actual artifacts as well as scores.

Measure returned guidance text from captured successful cat, numeric sed and
heading-only rg operations. Include repeated reads and heading inventories;
report entry and reference text separately. Do not substitute file/topic counts
for read extent. Do not require fewer reads when an actual decision needs more.
This is observable returned text, not serving tokens, total context, latency or
billing. Compare within the same task; six examples are not a population estimate.

For any verdict decline, new failure item or normalized score drop of at least
one point, inspect the artifacts and generate one more paired run using the
same configuration. Preserve first attempts and repeats separately. Capture or
service errors remain invalid evidence, not low-quality success; retain the
error and inspect it before any repaired run. If a real defect warrants guidance
refinement, freeze it separately and retain the original condition and failure.

Validate the entry/reference links, section-link failure detection, capture
recognition and protection boundaries with the existing validator and script
tests. Confirm frozen guidance bytes and captured protected checks before local
activation. Follow the established receipt, lock, backup, post-check and restore
workflow; keep the formal release version unchanged for a local development run.

Limits include one model family for generation and grading, no human handoff,
automatic selection or multiple-skill experiment, no production account or
physical-device performance proof, and no universal guarantee of future quality.
