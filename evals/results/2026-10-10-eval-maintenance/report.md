# 评测链路修复与多文件审查用例验证

日期：2026-10-10。修复前脚本取自 `469a44dedea4d7effdbe74a65fe6e1d1f439637a`。
本记录验证采集、评分与用例本身，不构成 Skill 发布或检出率提升证明。

## 五项修复

| 问题 | 修复后的行为 | 回归方式 |
| --- | --- | --- |
| 旧评分缓存掩盖新证据 | 两阶段缓存绑定输入、契约、证据、配置及输出摘要；无摘要旧缓存重算 | 改回答、diff、日志、规则、rubric、路由、配置及快照，确认重新评分 |
| 失败或污染采集仍得 target | 生成失败、隔离未建立、读取证据未知、关键产物缺失及保护文件被改写为 invalid | 先制造通过记录，再注入无效采集，确认覆盖旧结论且不调用评分模型 |
| 选择新增案例后合并丢失 | 按案例 ID 更新并追加，保留未选择案例 | 在已有结果后选择新 ID，检查两者均保留 |
| 超时日志 bytes 崩溃 | 超时输出统一解码为文本，保留退出码 124 | 模拟含非 UTF-8 字节输出，并运行真实超时子进程 |
| 文件名出现被当作阅读 | 只认成功的明确读取；列目录不计；通配符等不明访问标 unknown | 目录枚举、显式读取、shell 包装、变量、通配符、失败读取及越界路径 |

五组核心回归放回修复前脚本后全部暴露问题，产生 14 个子断言失败和 1 个 bytes 类型错误，
见 [修复前日志](regression-before.log)。当前完整测试集 **54 项通过**；官方 Skill 校验、
仓库校验及 diff 空白检查通过，详见 [验证日志](verification.log)。评分流程测试替换了
外部模型调用，但实际执行读写、缓存失效、结果合并和 verdict 处理。

## 新审查用例

新增完整审查与有限范围审查两个案例，共用 before/after 快照：34 个变更文件，
486 行新增、74 行删除，after 共约 570 行。包含分散的需求、已批准修订与未批准草案、
UI 到控制器的调用关系、未变化却遗漏新增职责的恢复入口，以及正确的本地状态例外。

原有 10 项 Node 测试全部通过。维护者侧通过公开接口复现四处契约缺陷：
无 ID 获取按钮未禁用、目录未恢复、Retry 使用编辑后的草稿、新查询失败后复用旧游标。
前三项预埋，第四项由独立审查发现后核实并补入标准；原始 reviewer 输入未因此改动。
在临时副本应用四处针对性修复后，同一套公开行为检查通过。
这些检查不会复制进 reviewer 工作区，也不会进入盲评提示。

审查采集现在冻结原始需求和代码快照供两个评分阶段使用，并检查被审文件未被修改。
输入摘要见 [input-hashes.json](input-hashes.json)。该夹具更接近混合变更，但并非
7,660 行生产 diff 的等量替代，也没有提供可运行的 React 宿主或浏览器环境。
