+# `@frontend-architect-eval/feature-flags`
+
+Vite plugin that exposes a client-safe subset of JSON feature flags through `virtual:feature-flags`.
+
+## Usage
+
+```ts
+import { featureFlags } from '@frontend-architect-eval/feature-flags'
+import { defineConfig } from 'vite'
+
+export default defineConfig({
+  plugins: [
+    featureFlags({
+      source: new URL('./flags.json', import.meta.url),
+      expose: ['checkoutV2', 'theme'],
+    }),
+  ],
+})
+```
+
+```ts
+import { flags } from 'virtual:feature-flags'
+
+flags.checkoutV2
+flags.theme
+```
+
+## Public Types
+
+The package exports:
+
+- `featureFlags(options)` as the plugin factory
+- `FeatureFlagsOptions` for user config
+- `FeatureFlagPrimitive` and `FeatureFlagsShape` for shared type contracts
+- `@frontend-architect-eval/feature-flags/virtual` as the fallback ambient module
+
+At runtime the plugin also writes `src/feature-flags.d.ts` in the consuming app so `virtual:feature-flags` resolves to the exact exposed keys.
+
+## Diagnostics
+
+The plugin fails fast when:
+
+- `source` is not valid JSON
+- the JSON root is not an object
+- `expose` is empty
+- an exposed key is missing
+- an exposed value is not a primitive
+- an exposed key looks like a secret (`token`, `secret`, `password`, `privateKey`, `accessKey`)
+
+Each error includes the file path and a concrete action.
+
+## Source Maps
+
+Generated client modules return a sourcemap shell that points back to the source file path without embedding the raw JSON content. This keeps browser debugging usable without leaking unexposed values into `.map` files.
+
+## Cache And HMR
+
+The plugin caches the parsed snapshot per Vite process. On file changes it invalidates the cache, regenerates the declaration file, invalidates the virtual module, and serves the new public flags in both dev SSR and browser HMR flows.
+
+## Package Exports
+
+`package.json` exposes:
+
+- `.` for the runtime plugin and its declarations
+- `./virtual` for ambient module typing
+- `./package.json` for tooling that inspects package metadata
+
+## Integration Testing
+
+The workspace exercises:
+
+- build output and sourcemap leakage checks
+- dev server SSR + HMR consistency
+- actionable diagnostics on bad configuration
+- packed-package consumption after `npm pack`
+
+## Versioning
+
+Recommended version evolution:
+
+- `0.x`: allow iteration on option names and generated declaration shape
+- `1.0`: freeze `virtual:feature-flags` exports and error contract
+- minor releases: additive options only
+- major releases: any change to generated module shape, type names, or diagnostics semantics
