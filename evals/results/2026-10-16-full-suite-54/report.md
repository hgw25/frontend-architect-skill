## Dialog 原因与证据

[完整诊断](dialog-diagnostics/report.md) 保留三个历史产物的失败与受控修正：

1. 生成阶段的 Mach IPC 启动拒绝是执行环境限制；宿主能运行浏览器。该限制并非所有新运行都出现。
2. 旧产物的 `process is not defined` 和 Playwright TSX → React SSR 的 `__pw_type` 错误属于生成的测试构建/转换问题。仅修正 harness 后，同一组件的 5 项浏览器检查通过；不把原失败改成通过。
3. 初版 150 行产物的外部点击焦点丢失是真实事件时序缺陷：清理阶段恢复触发器焦点后，鼠标默认行为又移走焦点。原 2/3，通过局部诊断修正后原检查通过；仍不计入正式原样本通过数。
4. 更早的超时部分产物包含空区域可见性和 inert 背景触发器查询的测试条件问题；诊断副本修正消费者内容和 metadata 定位后 6/6，原超时仍无效。
5. 本轮 151 行首轮产物确实通过构建期 SSR 注入和真实 `hydrateRoot` 路径，3 项浏览器检查在生成和宿主记录中都通过。曾因只读源 HTML 漏查构建转换而提出的“不曾水合”假设已被受控重放否定并撤回。
6. 本轮旧版 276 行恢复产物也出现相同外部点击焦点竞态：原样重放 3/4，独立诊断副本局部修正后同一组检查 4/4。该缺陷不是精简版独有。其首次独立评分为 12.8/16、fail，宿主检查失败保持不变。见 [恢复产物的证据](dialog-diagnostics/recovery276/results.json)。

7. 预注册复测中，旧版 Dialog 宿主检查通过、13.6/16 target；当前版虽然生成正常结束，但一次读取进程创建失败使捕获无效，且宿主真实浏览器为 3/4，仍有相同焦点竞态。独立副本恢复包构建前提后原样复现；只修正一处事件默认行为，同一完整检查通过。正式样本不改判。见 [当前版复测诊断](dialog-diagnostics/repeat151/results.json)。

因此，Dialog 包含**执行环境限制、生成的测试构建问题和真实实现缺陷**，需要分别归因。最终 151 行复测也再次使用“可发布”表述，虽披露浏览器受阻，但就绪结论仍超出实际验收证据；这是指导执行与交付判断不可靠的具体反例。两版均有完整交互和证据边界要求，且长版也出现同样焦点缺陷，不能唯一归因为精简删除了某条规则。

## 维护判断

本轮未发现函数职责、操作所有权、适度抽象、真实信任边界与自主执行这些关键场景出现普遍回退，但有真实局部遗漏和复现的路由约束失败，不能标记为“稳定无退化”。单模型、固定旧版先运行、有限次数生成和同模型家族评分，也不足以证明总体等价。

后续改进应落在已确认的责任处：交互缺陷由实现和可执行验收闭环处理；路由先区分标题发现、正文读取与具体决策缺口，调整口径后冻结新协议对照，不在本轮事后放宽；评分证据应能辨别中途失败后已修复与最终仍失败。现有指导已经要求完整交互、证据边界和相称工程判断，本轮没有为单个 Dialog 实现再增加全局事件规则，也没有通过继续加重入口来修复工具问题。
