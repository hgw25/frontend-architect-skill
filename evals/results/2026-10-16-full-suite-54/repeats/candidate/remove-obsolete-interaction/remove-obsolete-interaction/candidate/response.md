结论：把“会话面板”从可调高度抽屉机制中退出，改为只维护打开/关闭状态和拖动期间的临时位移；公共可调高度抽屉及其他调用方保持不变。不要新增 `disableDocking` 一类兼容开关继续保留废弃逻辑。

当前仓库 `HEAD` 没有实现文件、测试或包配置，除 `.frontend-architect` 外为空，因此无法确认五个参数的实际名称和具体文件位置。以下方案是可执行边界，但落地时必须在真实源码中按调用链核对命名。

## 最小重构方案

| 范围 | 处理 |
| --- | --- |
| 会话面板状态 | 删除持久化的 `sheetHeight` 及其 setter/ref；只保留打开/关闭状态。拖动只使用动画系统内部的临时 `translateY`。 |
| 停靠机制 | 删除 60% 停靠判断、停靠动作、隐藏按钮及其仅供会话面板使用的事件、埋点和测试分支。 |
| 高度监听 | 删除专门同步 `sheetHeight` 的 `heightListener` 注册、回调和清理。若它同时承担旋转、安全区或窗口尺寸更新，保留那部分通用职责并改由布局约束消费。 |
| WebView | 删除中间高度绘制补偿。WebView 使用全高容器的正常布局（如 flex/约束布局）；拖动时移动整个面板，不逐帧改变 WebView 高度。 |
| 五个透传参数 | 从会话面板入口开始，逐层删除参数、类型、默认值、转发和测试 fixture，直到真实消费者。若这些参数属于公共可调高度抽屉的公共契约，只删除会话链路中的透传，不修改公共 API。 |
| 展开与收起 | 展开直接进入全高。头部向下拖动达到现有关闭条件时，调用项目已有的全高收起动画。短拖松手则回弹到全高，不产生第二个稳定高度。 |
| 公共抽屉 | 保留可调高度状态、监听器、任意高度绘制及其现有 API，避免影响其他页面。 |

建议优先让会话面板使用项目已有的固定全高/收起入口。若现有公共抽屉只能通过可调高度机制工作，再增加一个很薄的会话专用适配层，仅组合“头部手势 + 现有收起动画 + 全高内容”；不要为了一个已简化的页面给公共抽屉增加更多模式开关。

最终依赖关系应是：

```text
会话面板
  ├─ open / closed
  ├─ 头部拖动临时位移
  ├─ 已有全高收起动画
  └─ 全高 WebView 布局

其他页面
  └─ 公共可调高度抽屉（保持原契约）
```

## 验证计划

1. 静态与调用链检查

   - 搜索 `sheetHeight`、`heightListener`、停靠按钮标识及五个参数的真实名称。
   - 确认它们不再出现在会话面板及其包装层中。
   - 确认公共抽屉和其他页面的引用仍存在。
   - 运行项目既有类型检查、lint 和相关测试，利用类型错误发现遗漏的参数透传。

2. 会话面板交互测试

   - 打开后直接全高展示，不经过或停留在 60%。
   - 从头部向下拖动达到关闭条件：执行既有收起动画并最终关闭。
   - 短距离拖动后松手：回弹到全高，最终没有 60% 或其他中间稳定状态。
   - 回弹过程中再次拖动、快速连续拖动：动画可被正确接管，不跳位、不误关。
   - WebView 内部滚动不误触发头部收起手势。

3. WebView 与布局实机验证

   - 在实际设备或模拟器上观察展开、拖动、回弹和关闭。
   - 确认 WebView 无白屏、空隙、闪烁、滚动位置跳变或逐帧重排。
   - 覆盖至少一个长页面，并检查旋转、窗口尺寸变化和安全区；这一步用于确认被删除的监听器没有夹带必要的视口职责。

4. 公共能力回归

   - 选择一个仍使用公共可调高度抽屉的页面。
   - 验证其自定义高度、拖动、监听回调和既有停靠行为保持不变。
   - 现有公共抽屉测试应无需为了会话面板重构而改写。

5. 验收标准

   - 会话面板不存在可持久化的中间高度。
   - 删除的是完整旧机制，而不只是隐藏入口。
   - 五个参数不再穿过会话调用链。
   - 公共可调高度抽屉契约和其他页面行为不变。
   - 后续若调整会话面板的关闭阈值或取消拖动，只需修改会话面板边界，不触及公共抽屉。
