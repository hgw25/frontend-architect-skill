# 默认需求开发流程的定向验证

日期：2026-10-19。源码基线：`250883b`（v0.5.0）；本次为未发布开发修改。

结果：最终两项独立实现均主动先保存技术设计，再修改源码；功能验收、四张图的语法解析
及独立盲评均通过。原始失败和误判未删除。综合判定见 [outcomes.json](outcomes.json)。

## 原问题与修改

旧指导要求必要时记录简短计划，无法保证只给业务需求就产生先行技术设计。
新入口明确要求新业务流程、职责重构、共享基建和迁移在改实现前保存技术文档。
详细指导连接需求、明确计数且按依赖排序的实施步骤、每步功能与验收、实际模块/类型/
函数或类契约、技术架构图和数据流转图；实施中修订，交付时回填实际证据。
既定文案、间距和局部接线保留轻量路径，设计不增加审批门槛，也不强制类或抽象层。

## 输入与隔离

两个新增需求为条件字段与导出职责重构。原始业务 prompt 没有文档、图、实施步骤等
提醒；测试只说明产品行为。生成代理仅获得原始代码、需求及当前条件的技能副本，
看不到本次聊天、参考方案、`must_observe`、`fail_if`、rubric 或其他组结果。
原始请求见各条件的 `prompt.txt`；完整输入与指导快照见 `frozen-inputs/`。

模型：`gpt-5.6-sol`，reasoning effort：`medium`，Codex CLI：`0.145.0`。
生成使用仓库既有采集器的 `--ephemeral --ignore-user-config`、独立临时 Git 工作区、
关闭插件及多代理等配置；运行事件审计了局部技能加载和指导隔离。
无技能、修改前技能及两轮新指导使用相同模型和参数。两个新增用例均为可执行夹具，
宿主复跑保护测试并检查保护文件未改。产物同时保存在各条件的 `artifacts/`，不依赖临时路径。

## 控制与检查

首轮新指导的局部文案修改和文档深度判断均完成并经独立盲评判 `target`：文案直接修改，

新夹具原有契约 7/7 通过；新增功能检查在起始实现为 1/6 通过、5/6 失败，确认能暴露缺失。

图示检查使用 Mermaid 12.2.0 与 jsdom；脚本和精确版本记录见 `execution/check-diagrams.mjs`
及各条件的 `diagram-checks.json`。这证明解析成功，不等于浏览器布局或视觉质量已验收。

gpt-5.4 与 gpt-6.1-sol 在本机 CLI 账户上不受支持，任务没有执行，相关目录只保留无效
采集证据，不计入质量比较。确认可用模型后全部有效比较统一使用 gpt-5.6-sol。

## 复现方式

1. 创建只包含技能、references、CONTRIBUTING、脚本及所选夹具的隔离源码根。
   用对应 `SKILL.snapshot.md` 恢复为该根的 `SKILL.md`，使用最终评分条件时复制
   `scoring-cases.yaml` 至 `evals/cases.yaml`，不把这些评分条件交给生成代理。
2. 使用 PyYAML 开发依赖运行该根 `scripts/run_behavior_evals.py`，选择
   `requirement-only-conditional-fields` 和 `requirement-only-export-refactor`，
   `--model gpt-5.6-sol --reasoning-effort medium --mode candidate`，使用新结果目录。
   无技能比较改为 `--mode baseline`。
3. 用既有 `score_behavior_evals.py` 在独立上下文盲评；同目录评分配置保持一致。
4. 用 `execution/collect-artifacts.py <结果目录>` 保存实际产物和写入事件；在临时目录安装
   Mermaid 12.2.0 和 `diagram-checks.json` 记录的 jsdom 版本，执行
   `node execution/check-diagrams.mjs <该临时目录/node_modules> <结果目录>`。
   原始失败条件的解析命令应返回非零，不能被模型评分覆盖。

## 证据边界

这是两个小型 JavaScript 前端能力的定向试验，包含原指导和无技能对照及图示问题后的
重新生成，不能据此宣称所有需求或模型稳定达标。生成与盲评使用相同模型系列的独立
上下文，有相关性限制；维护者另外核对真实写入顺序、代码契约、保护测试与图示解析。
没有重跑完整 56 例，也未验证自动技能选择、复杂类生命周期场景或真机/浏览器行为。
