最小方案是让“会话面板”彻底退出可调高度协议，直接复用现有全高收起动画；公共可调高度抽屉及其 API 保持不变。不要新增 `fullHeight` 开关来包住旧逻辑，也不要仅把五个参数传成空值，否则遗留状态、监听和绘制补偿仍可能执行。

## 重构范围

会话面板改成单一布局状态：

```text
打开：全高
头部下拖超过既有阈值：执行现有收起动画
头部短拖松手：回弹到全高
不存在：60% 停靠、中间高度、按高度重绘 WebView
```

具体改动顺序：

1. 在会话面板入口切断可调高度能力。

   - 不再创建或更新 `sheetHeight`。
   - 删除 60% 停靠值、停靠判断和隐藏的停靠按钮分支。
   - 头部手势只维护拖动期间的临时位移；不要把位移转换成持久高度。

2. 收敛拖动结束逻辑。

   - 达到既有关闭距离或速度阈值时，调用项目已有的全高收起动画。
   - 未达到阈值时，将位移回弹到零。
   - 删除任何“选择最近停靠点”或落到中间高度的分支。
   - 优先整体平移面板，避免拖动期间持续改变 WebView 布局高度。

3. 删除会话链路的 `heightListener`。

   - 删除注册、回调、清理和为监听结果设置高度的逻辑。
   - 若该监听属于公共抽屉内部，则不要修改公共实现；会话面板应改为不经过这条可调高度调用路径。
   - 全高尺寸应由现有容器布局决定，并自然响应可用区域变化，而不是重新建立一套窗口高度监听。

4. 删除 WebView 的中间高度绘制补偿。

   - 移除仅为 60% 停靠服务的高度计算、样式覆盖、刷新或重绘触发。
   - 保留独立成立的安全区、键盘避让和 WebView 生命周期处理；不能因为同样涉及高度而一并删除。
   - WebView 始终填充会话面板的内容区域。

5. 从会话组件链逐层删除五个高度相关参数。

   - 同步删除 props 类型、默认值、中间组件透传、调用处、测试夹具和 mock。
   - 不要合并成一个新的 `sheetOptions` 对象，也不要保留废弃兼容参数。
   - 公共可调高度抽屉自己的五个参数或等价 API 继续保留，因为还有真实消费者。

预计只需修改会话面板协调层、头部手势层、WebView 容器及对应测试；公共抽屉原则上零改动。只有当现有全高收起动画无法被会话入口直接调用时，才增加一个很薄的会话专用适配层，不扩展公共抽屉模式。

## 验收条件

- 每次打开都直接全高展示，不出现 60% 帧或二次跳变。
- 只有从头部开始的下拉手势能够收起；WebView 内滚动不改变面板高度。
- 短拖松手回到全高，过程中不落到中间位置。
- 达到关闭阈值后只执行一次现有收起流程。
- 窗口尺寸或方向变化后仍填满可用区域。
- 会话面板运行时不再注册 `heightListener`，WebView 不再收到中间高度更新。
- 其他页面的公共可调高度抽屉仍能改变高度和停靠。

## 验证计划

1. 静态与类型检查

   - 搜索会话功能目录，确认不再存在 `sheetHeight`、60% 常量、`heightListener`、中间高度补偿以及五个参数的定义或透传。
   - 运行项目既有类型检查，利用 props 调用错误确认整条透传链已清干净。
   - 单独确认公共抽屉及其其他调用方仍保留可调高度契约。

2. 交互测试

   - 打开面板：断言为全高。
   - 头部短距离下拖后释放：断言面板仍打开且回到初始位置。
   - 头部长距离或快速下拖：断言现有关闭回调和动画只触发一次。
   - 模拟原中间高度事件：断言会话面板布局不受影响。
   - 在 WebView 内容区滚动：断言不会触发面板拖动或高度变化。

3. 共享能力回归

   - 选择一个仍使用公共抽屉的代表页面，覆盖展开、改变高度、停靠和关闭。
   - 这项测试应通过公共组件的可观察接口完成，防止为了会话面板误删共享行为。

4. 目标运行环境检查

   - 至少覆盖一个窄屏和一个较高屏幕，以及方向或窗口尺寸变化。
   - 检查安全区、WebView 内容底部可达性、拖动中断和连续快速拖动。
   - 用布局/性能工具确认拖动期间主要是面板位移，不再持续触发 WebView 高度布局和重绘。
