## P2 — 实际指导副本改变或删除后，捕获仍被判为有效

位置：[run_behavior_evals.py](../../../../scripts/run_behavior_evals.py) 的
`initialize_workspace`（118–134）、`capture_attempt`（658–672）及源指导摘要（722–724）。
`.frontend-architect` 被 Git 排除，既不进入项目 diff，也不进入项目快照；manifest 记录
源 skill_root 的摘要，每次生成后没有核对实际工作区指导副本的文件集合及字节。

独立探针以本地确定性生成器替代外部模型，真实执行命令并使用原 runner 和证据 gate。
一个对照完整读取指导后执行 `git clean -fdx` 删除指导目录；另一个先改变指导文本再
完整读取。两者 capture 都返回 0，阅读审计 recognized/local_skill_read=true，
`capture_errors` 和 `captured_evidence_errors` 均为空。
主审已原样复跑，见 [删除探针输出](capture-consistency-probe.log)、
[改变后读取输出](mutated-guidance-probe.log)及相应 `.py` 源码。

因此记录不能独立支持实际使用的副本就是 manifest 指向的冻结字节。这是指导末态
一致性接线缺失，不要求事件审计识别任意 shell 内部行为。
建议复用已有摘要方式，在初始化和每轮结束核对副本身份，并让失配/缺失进入 invalid；
同时为这些反例补回归，不宣称末态摘要能发现后来恢复的所有中途修改。

## P2 — 保存的独立验收输入改变或丢失后，评分证据 gate 仍接受

位置：[score_behavior_evals.py](../../../../scripts/score_behavior_evals.py) 429–432；保存端
位于 runner 771–776。评分目前只比较 `input_artifacts` 中的摘要映射和捕获契约记录，
没有读取 `acceptance-inputs/<source>` 的实际文件来检查存在性及摘要。

同一真实 runner 探针完成独立消费者检查后，依次改写、删除保存的 oracle.py；不改
源 oracle、manifest 或执行日志。两个评分证据 gate 结果仍为空，主审已复跑。
这不证明当时消费者未执行，但保存用于复核的输入已经失配/丢失，仍被标为有效。

建议沿用相邻 `attempt_artifacts` 的存在性、目录内路径及实际摘要核验，检查所需的
冻结 acceptance 文件。能恢复匹配原摘要的输入时保留其来源，否则重新采集；不要只
比较两个记录字段，也不要通过新增提示词替代工件检查。

以上两项的独立审查、准确位置及能力边界详见 [执行链审查](evaluation-review.md)。
探针不是生成模型轨迹或质量实验，其 exit 0 只表示探针成功执行；空错误列表是本轮
观察到的缺口，不能作为功能成功样本或评分结果。

## P2 — 旧资料用例的检查入口可被改写，确定性检查绿色不代表原验收执行

位置：[cases.yaml](../../../../evals/cases.yaml) 的 `optimistic-profile-update`（1663–1695）：
仅声明 `npm ci` / `npm run check`，没有 protected_paths 或独立验收；runner 的
`validate_protected_paths` 在没有声明时直接返回 None。

主审在隔离副本运行原验收，得到 exit codes `[0, 1]`。只把该副本 package.json 中
`scripts.check` 改为 `node --version`，未修改源码或原测试，再运行同一个 `validate_fixture`，
得到 `[0, 0]`。保护检查仍为 None。完整命令输出与身份见
[legacy-harness-entry-probe.json](legacy-harness-entry-probe.json)。

这证明该用例缺少一个不能被候选修改的检查入口，不证明后续模型审查必定会放过这种
变化。当前会退化为依赖模型从 diff 中识别验收被替换。建议用现有 protected_paths
保护真正的验收文件/入口，或通过 acceptance_checks 独立运行冻结消费者；对允许改动
的测试和公开 package 清单保留合理修改空间，不机械锁死所有产品文件。
