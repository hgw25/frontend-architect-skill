# 整体工作流与局部深度的边界修订

2026-11-12。用户要求把技能整体开发流程作为宏观工作流约束，修正上一轮轻量文档
可能被理解为裁剪流程的问题。初始计划及完成记录沿用
[工程记录](../../../docs/engineering/principles-to-implementation.md#固定整体工作流与阶段完成条件)。

## 已完成的指导修改

- `SKILL.md` 集中保存六阶段与完成条件：需求/现状、功能/验收、方案/契约、实现、
  行为验证/工程审查、成果对齐/交付。阶段可合并简短执行，并根据事实和失败返回
  相关决定迭代；不是只允许执行一次的串行瀑布。
- 明确局部方案的调整权限：可以改变机制、边界和深度，不能豁免阶段、重定义已接受
  行为、扩大授权或将未验收结果记为完成。免独立文档只影响产物形式。
- 用户决定完整开发、仅设计或仅审查的交付边界。设计自审和拟议验证可关闭设计任务，
  不要求实现应用；评审完成需求/代码/证据检查后报告，不自动进入开发。
- 任务表、设计准备及交付段落回指同一工作流。架构与验证专题只连接这一入口；
  README、rubric、评测协议和第二阶段审计同步这一边界，不要求六份阶段报告、状态
  台账、固定标题或新增审批。

`cases.yaml` 增加可复用的 `workflow_completion` 验收条件，选择在窄规则、搜索/资料、
完整开发、仅设计与两种只读审查代表任务中使用。新增 `workflow-stages-and-local-depth`
反例，检查实质遗漏、正确轻量闭环、失败后的反馈及仅设计越界。现有
`score_behavior_evals.py::build_failure_prompt` 提醒审查声明的工作流条件，继续按实际
产物和执行证据判断，不用缺少阶段旁白推定动作未执行。

没有新增阶段执行器、程序状态机、产物生成器、评分字段、安装或发布流程。
这是技能指令和既有验收的完成条件，不声称具有运行时逐步拦截能力。

### 窄规则的真实实现

实际产物仅在原 schema 的 taxId 字段上补条件必填；校验与提交共用原有能力，未加
独立设计、两图、阶段日志或新框架。原始两项失败在修改后消失，全部六项检查通过，
受保护文件与本地指导字节不变。主审检查了实际差异与公开消费者，宿主独立复跑通过。
见 [实际项目](implementation/project-final.json)、[差异](implementation/changes.patch)、
[生成方日志](implementation/agent-validation.log)、[宿主结果](implementation/host-validation.json)。

这支持该次局部实现、调用一致性与相称产物，没有完整原生工具事件，不能独立证明
每个内部判断发生的顺序。没有阶段标题或专门文档不作为缺陷。

### 工作流与准备深度判断

独立答复 [工作流反例](judgments/response-1.md)能区分 A 的明确省略与 B 的实际轻量动作：
A 需补契约、方案、实际代码检查及适用验收，B 不需要补六份文件。C 的失败重开受
影响的决定并保留已验证独立工作，不能仅标风险就算完成；D 应在设计自审和设计
交付处停止，不能为了补齐开发阶段而写应用、启动未授权服务。

[准备深度答复](judgments/response-2.md)保留统一登录迁移的先设计、实施增量、具体契约
和两视图，同时允许按钮、既有 URL 绑定及条件必填轻量实施，并保留代码检查与验证。
两份答复均限定为题给记录判断，没有将拟议检查写成已运行应用的证据。

## 最后核对与证据边界

独立任务之后回读时，发现原入口仍有旧句 `Task size changes scope`，已明确改成
用户设置交付范围，任务大小调整设计与验证深度。新工作流本已明确用户决定终点；
这次统一旧段落措辞，防止误读。两份指导分别保存在 `frozen-guidance/` 和
`final-guidance/`，实际生成输入保留原样，不冒充与最后入口逐字节相同。

最终指导经另一个不见前两份输出的独立上下文核对，未发现宏观阶段、轻量设计、反馈
返工及授权终点间需要修改的具体矛盾。见 [最终指导审查](final-guidance-review.md)。
这项检查针对最后冻结文本，不把先前实际生成输入重标为最终字节，也不证明每次代理
都会遵循阶段要求。最后结构/官方校验与空白检查通过，身份及工具摘要见
[metadata.json](metadata.json)，最后命令见 [final-checks.json](final-checks.json)。

本轮无完整原生事件、准确模型 ID/effort、标准两阶段盲评分、同条件基线或多次重复；
不计算流程稳定率或技能收益。没有运行全量 84 个模型场景，也没有浏览器、真实服务、
App/小程序真机或生产验证。已有历史结果和冻结指导均保留原内容与原协议。
