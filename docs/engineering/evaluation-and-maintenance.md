# 评测验收与安装维护设计

本次修复针对四个已复现的问题：实现盲评缺少原始契约与未改动代码；必要成果遗漏仍可被
平均分抵消；打包消费者检查只看 hook 形状；根目录安装与独立维护技能产生重复发现。
原有请求、fixture、技能指导和受保护检查继续区分来源。历史结果不重新标成新版协议有效。

## 实施顺序

共四步，前两步提供后续验证所需的可信输入和判定方式。

1. **保存实际项目上下文。** 采集原始项目和每次交付的完整受版本管理文件及新增文件，
   排除 Git、依赖、临时构建。保存文本、非文本摘要与来源哈希；给盲评提供原始契约、
   最终定义及调用方。锁文件正文可在评分输入中省略，但原始快照保留且明确披露。
   验收包括未改动契约、常规 `sed` 读取、早期检查和缺失/变化快照。
2. **独立验收必要成果。** 复用两阶段评分；第一阶段仍隐藏预期观察项，第二阶段根据
   原始需求/项目契约检查完整性，并检查按适用范围选择的共用验收条件。逐项给出满足、
   不满足或证据不足及定位。后两者阻止 `target`，不由均分覆盖。机制不匹配固定标题、
   函数名或实现模式。新旧案例共用同一判定机制，局部编辑不强制设计或性能基线。
3. **通过包的真实消费者验收。** 在独立目录安装 tarball 后执行类型检查、Vite 构建和
   开发模式消费；核对公开值、更新和秘密隔离。正常实现应通过；空 hook、空公开声明、
   泄漏或失效实现应失败。工作区测试不能代替打包后的消费结果。
4. **统一安装维护与独立复测。** 维护子技能负责发现版本和调用官方下载器；受信任的
   本地执行器负责检查、归一化、锁、备份、激活、校验及恢复。README 只保留该入口。
   注入激活/校验失败验证恢复；最后以原始需求和冻结技能完成独立生成，不泄露本轮诊断、
   验收条件、oracle 或修法。分别记录首次结果、检查暴露的遗漏及允许的修复结果。

## 责任与代码契约

初版在源码修改前落盘；以下契约已按当前定义与调用链核对，并在同一记录回填实施结果。

| 所有者 | 契约及数据流 |
| --- | --- |
| `scripts/eval_evidence.py` | `project_snapshot(workspace: Path) -> dict[str, Any]` 读取项目实际文件；`save_snapshot(path, snapshot) -> str` 返回文件摘要；`snapshot_errors(path, digest, expected_files=None) -> list[str]` 验证完整性与原始契约；`project_context(case_dir) -> str` 提供正文和未变化引用 |
| `scripts/run_behavior_evals.py` | `capture_attempt(args, case, workspace, baseline, directory, prompt)` 执行生成和宿主检查后保存最终快照；`run_acceptance_checks(case, workspace, timeout) -> list[dict[str, Any]]` 在副本执行独立消费者；`acceptance_source(case, source, root) -> bytes` 优先使用已冻结支持文件 |
| `scripts/score_behavior_evals.py` | 两阶段都消费冻结原始/最终项目上下文；`validate_failure_audits` 校验完整的契约审查和逐项验收，`finalize_evaluations` 保留质量分但以必要成果和实际消费者结果决定达标 |
| `evals/cases.yaml` | 共用验收 profiles 和案例的适用引用；仅第二阶段看到，既不提供实现答案，也不自动扩大所有任务范围 |
| 两个 flags fixture 的 `scripts/check-package.mjs` | 从已安装包的公共入口执行实际宿主消费，临时消费者自行清理；不导入工作区源码 |
| `skills/frontend-architect-update/scripts/manage_installation.py` | `inspect_installation(destination)` 返回版本和摘要；`activate(candidate, destination, backup_root, *, baseline=None, replace_local=False, tag="", commit="", expected_current=None, operation="activate", skill_name=NAME)` 返回完成回执或 unchanged；`rollback(destination, backup_root, *, receipt_path=None, replace_local=False, skill_name=NAME)` 经同一事务恢复。不联网、不执行候选脚本 |

重要边界：评分上下文不能把生成方自述当成原始需求；主持方之后运行的检查不能冒充
模型自主运行；快照完整性与语义正确性分别判断；缺证据不得伪装成已验收。安装的候选
与当前版本分别校验，本地变更与来源未知必须按现有授权处理，失败保留可恢复的数据。

## 技术架构

```text
维护者案例/原始 fixture ----> 采集器 ----> 隔离生成工作区
                                  |             |
冻结技能 -------------------------+             +--> 实际代码/文档
                                  |             +--> 自主检查事件
                                  v
                      原始/最终快照 + 原始事件 + 公开/独立消费者检查
                                  |
                                  v
                 第一阶段质量评分 -> 第二阶段契约/必要成果审查
                                  |                    |
                                  +---------> 最终判定 <+

README -> 独立维护技能 -> 官方下载器 -> 暂存不可变版本
               |                            |
               +--> 本地安装执行器 <---------+
                         |
                   检查/归一化/锁
                         |
                备份 -> 激活 -> 核对 -> 完成回执
                         | 失败
                         +------> 恢复原安装并保留失败回执
```

## 数据流

```text
短请求 + 项目原始输入 + 冻结技能
 -> 保存原始快照与契约
 -> 独立生成 -> 保存回答和事件
 -> 宿主运行公开检查 -> 在隔离副本运行预先冻结的独立消费者
 -> 保存每轮最终快照与实际检查结果
 -> 验证摘要/契约/隔离
      -> 无效输入：invalid，要求重新采集
      -> 有效输入：盲评质量 + 原始契约审查 + 必要成果逐项审查
           -> 不满足/证据不足/消费者失败：fail，保留定位和质量分
           -> 必要成果满足：按质量分区间给出结论

安装请求 -> 官方下载暂存 -> 校验候选身份及当前版本差异
 -> 取得独占锁 -> 再核对当前文件 -> 归一化候选
 -> 原目录移入外部备份 -> 同文件系统激活 -> 核对文件摘要
      -> 成功：完成回执，释放锁
      -> 失败：恢复原目录，记录失败；保留候选及恢复资料，释放自己的锁
```

## 验证与后续变化

检查原始契约被保留、遗漏不能被高分覆盖、失效包不能仅凭导入成功通过，以及首次安装、
更新和回滚的一致性。新增一种实际消费方式时，应扩展相应消费者检查而不改变通用评分
协议；增加一个新任务类型时，只选择真正适用的验收 profile，不复制一套评分器。

实施步骤 1–4 的源码已完成。118 项确定性回归通过，覆盖快照、必要成果、独立消费者、
同一目标不同备份位置的互斥、安装故障恢复及回滚。仓库结构及两项官方技能校验通过。
实际独立生成、校准正反例、命令原始输出与安装外部回执见
[本轮验收记录](../../evals/results/2026-10-19-evaluation-acceptance/report.md)。

最终看板的功能与独立检查通过，但不存在的文档符号使验收失败；插件真实消费者通过，
设计先行的事件顺序证据不足也阻止达标。原生代理邀请页补测通过 13 项自测、3 项冻结原始
检查及 4 项独立检查，最终契约与图示核对一致；它与 CLI 采集的审计能力分别报告。
缺基线及仅计划文档、伪造签名、空 hook 和空公开声明均被相应检查拒绝；真实对齐文档及
健康包通过。早期校准误判和容量中断保留，不作为改善证据，不以字段数量作为质量标准。
没有运行全部 71 项模型行为场景，也不据此证明远端发布或每次自主交付都无遗漏。
